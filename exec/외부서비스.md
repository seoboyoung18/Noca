| --- | --- |
| 가입 | 위 1번과 **같은 애플리케이션**을 쓴다 |
| 발급물 | **REST API 키** (로그인용과 같은 키를 쓸 수 있다) |
| 들어가는 변수 | `KAKAO_REST_API_KEY` |
| 값 | `[보안 정보 제외]` |

서버가 주소↔좌표를 변환하고 장소를 검색해 프론트에 좌표를 내려준다.

기본값이 **빈 문자열**이다. 가짜 값을 넣지 않는다 — 키가 있는 것으로 오인해 빈이 뜨고

위치 API 만 503 이며, **기동은 성공한다.**

일일 쿼터가 있다. 쿼터 초과(`-10`)와 파라미터 오류(`-2`)는 재시도하지 않는다.

| 가입 | https://console.cloud.google.com — 프로젝트 생성 후 **API 및 서비스 → 사용자 인증 정보** |

| 값 | `[보안 정보 제외]` |

### 콘솔에서 해야 할 설정

**① OAuth 클라이언트 생성** — 유형 **웹 애플리케이션**

**② 승인된 리디렉션 URI**

```
https://j15a307.p.ssafy.io/login/oauth2/code/google
http://localhost:8080/login/oauth2/code/google
```

**③ OAuth 동의 화면** — 앱 이름·지원 이메일 입력

### scope 는 `profile` 만 쓴다

`application.properties` 가 scope 를 명시하는 이유가 있다. 지우면
`CommonOAuth2Provider.GOOGLE` 의 기본값 `openid, profile, email` 이 적용되는데,
`openid` 가 있으면 Spring Security 가 **OIDC 흐름으로 분기**해
`CustomOAuth2UserService` 가 호출되지 않는다. 회원 조회와 가입 대기 판정이 통째로 건너뛰어진다.

provider 블록(authorization-uri 등)이 설정 파일에 없는 것은 누락이 아니다 —
구글은 Spring Security 에 내장돼 있어 자동으로 채워진다.

### 🔴 평가 전 반드시 확인

**게시 상태가 "테스트 중"이면 평가자가 로그인할 수 없다.** 등록된 계정만 통과한다(최대 100명).
앱 소유자는 테스트 사용자 목록에 없어도 로그인되므로, **본인 계정으로 성공하는 것은 검증이 아니다.**

**2026-09-23 조치 완료 — 게시 상태 `프로덕션`, 사용자 유형 `외부`.**
그전에는 `테스트 중` · 테스트 사용자 0명이라 평가자가 로그인할 수 없는 상태였다.
**등록하지 않은 다른 구글 계정으로 로그인해 약관 동의 화면까지 가는 것을 확인했다(2026-09-23).**
앱 소유자 계정은 게시 전에도 성공하므로, 이 "다른 계정" 확인이 유일한 검증이다.

> **"앱을 인증해야 합니다" 배너는 무시한다.** 인증(verification)은 **민감한 범위**를 요청할 때
> 필요하고, 이 앱은 `profile` 하나뿐이라 대상이 아니다. 인증 없이도 프로덕션에서 누구나
> 로그인되며 "확인되지 않은 앱" 경고 화면도 뜨지 않는다. 인증 센터에 제출하면 검토에 며칠이
> 걸리고 홈페이지 소유권 증빙까지 요구받는다.

확인 위치 (메뉴가 "Google 인증 플랫폼" 으로 옮겨졌다)

```
https://console.cloud.google.com/auth/audience     →  게시 상태
https://console.cloud.google.com/auth/branding     →  브랜딩 (게시 전제 조건)
```

## 5. AWS S3 (오브젝트 저장소)

| 항목 | 내용 |
| --- | --- |
| 가입 | https://aws.amazon.com — 계정 생성 후 S3 콘솔 |
| 발급물 | **버킷 2개** · **IAM 사용자 액세스 키** (아래 참고) |
| 들어가는 변수 | `STORAGE_STAGING_BUCKET` · `STORAGE_SERVICE_BUCKET` · `AWS_REGION` · `AWS_ACCESS_KEY_ID` · `AWS_SECRET_ACCESS_KEY` |
| 값 | `[보안 정보 제외]` |
| 리전 | `ap-northeast-2` (서울) |

### 🔴 자격증명 — 저장소의 서술과 운영이 다르다

저장소 주석(`build.gradle` · `backend/.env.example`)은 **기본 자격증명 체인**을 전제로 쓰였다 —
로컬은 `aws configure` 프로필, 배포 서버는 **EC2 IAM 역할**. 액세스 키를 두지 않는다는 설계다.

**그런데 실제 운영은 그렇지 않다.** 2026-09-23 BE 박스 확인 결과
`/etc/a307/backend.env` 에 **`AWS_ACCESS_KEY_ID` · `AWS_SECRET_ACCESS_KEY` 가 들어 있다.**

| 환경 | 자격증명 | 값 |
| --- | --- | --- |
| 로컬 개발 | `aws configure` 프로필 (`~/.aws`) | `[보안 정보 제외]` |
| **운영 서버** | 🔴 **정적 액세스 키** — `/etc/a307/backend.env` | `[보안 정보 제외]` |

**새 서버에 올릴 때도 이 두 값이 필요하다.** IAM 역할만 믿고 비워 두면 S3 호출이 전부 실패한다.

> **개선 과제** — EC2 인스턴스에 IAM 역할을 붙이고 `backend.env` 에서 그 두 줄을 지우면
> 키가 파일에 남지 않는다. 그렇게 바꾸면 이 절과 아래 IAM 권한 절도 함께 고쳐야 한다.
> 상세는 `포팅매뉴얼.md` **2-1** · **3-6** 참고.

### 버킷 2개의 역할 — 바꿔 쓰면 안 된다

| 버킷 | 내용 | 수명 |
| --- | --- | --- |
| `STORAGE_STAGING_BUCKET` | 브라우저가 presigned PUT 으로 올린 **원본**. EXIF(GPS·기기 정보) 포함 | 🔴 **7일 뒤 자동 삭제** (수명 주기 규칙) |
| `STORAGE_SERVICE_BUCKET` | 서버가 만든 **파생본**(RESIZED·THUMBNAIL), 견적서, 검증 PDF | 영구 보관 |

> 🔴 두 값을 바꿔 넣으면 **원본이 영구 버킷에 남고 파생본이 7일 뒤 사라져 이미지가 조용히 깨진다.**
> 배포 직후에는 정상으로 보이고 **7일 뒤에 드러난다.**

### 필요한 IAM 권한 (버킷 2개 모두)

```
s3:PutObject      presigned PUT · 파생본 저장
s3:GetObject      원본 읽기 · presigned GET(조회 URL)
s3:HeadObject     완료 통보의 3단 재검증(실제 크기 확인)
s3:DeleteObject   이미지 삭제 · 실패분 정리
s3:ListBucket     (선택) 운영 확인용
```

`s3:GetBucketLocation` 은 **필요하지 않다** — 리전을 코드에서 명시하므로 SDK 가 묻지 않는다.

> 🔴 **`AWS_REGION` 을 비우지 않는다.** 비우면 SDK 가 버킷 위치를 물어보려고
> `GetBucketLocation` 을 부르는데 IAM 정책에 그 액션이 없어 `AccessDenied` 로 죽는다.

### 버킷 수명 주기 규칙

staging 버킷에 **7일 후 만료** 규칙을 건다.
S3 콘솔 → 버킷 → 관리 → 수명 주기 규칙 생성 → 객체 만료 7일

### 프로필 이미지용 변수 (선택)

`PROFILE_IMAGE_STAGING_BUCKET` · `PROFILE_IMAGE_SERVICE_BUCKET`

같은 버킷을 가리키는 **두 번째 설정**이다. 이관 전까지 위 `STORAGE_*` 와
**같은 값으로 유지해야 한다** — 하나만 바꾸면 조용히 어긋난다.
없으면 프로필 이미지 API 만 503 이다.

## 6. SSAFY GMS (LLM 호출 프록시)

| 항목 | 내용 |
| --- | --- |
| 발급 | SSAFY 에서 팀 단위로 배부 |
| 발급물 | **GMS Key** (크레딧·만료일 있음) |
| 들어가는 변수 | `GMS_KEY` |
| 값 | `[보안 정보 제외]` |
| 기준 URL | `https://gms.ssafy.io/gmsapi` |

### GMS 는 LLM 이 아니라 프록시다

벤더의 원래 엔드포인트 호스트·경로를 기준 URL 뒤에 그대로 붙이고,
벤더 API 키 자리에 GMS 키를 넣는다. 요청 본문은 벤더 원본과 완전히 같다.

```
OPENAI → {base}/api.openai.com/v1/responses  또는  /v1/chat/completions   (Authorization: Bearer)
GEMINI → {base}/generativelanguage.googleapis.com/v1beta/...              (x-goog-api-key)
```

### 함께 맞춰야 하는 세 값

| 변수 | 기본값 | 운영값 |
| --- | --- | --- |
| `GMS_PROVIDER` | `GEMINI` | `OPENAI` |
| `GMS_MODEL` | `gemini-2.5-flash` | `gpt-5.4` |
| `GMS_OPENAI_API` | `responses` | `chat` |

> 🔴 **세 값을 반드시 함께 바꾼다.** `GEMINI` 인데 `gpt-5.4` 를 넣으면
> Gemini 경로로 OpenAI 모델을 보내 실패한다.

이 셋은 비밀이 아니라 `.gitlab-ci.yml` 의 `docker run` 에 `-e` 로 박아 리뷰 가능하게 둔다.
**`backend.env` 에는 적지 않는다** — 두 곳에 같은 이름이 있으면 `-e` 가 이겨서
`backend.env` 를 고쳐도 반영되지 않는다.

### 크레딧 보호

팀 공용 키라 실패한 호출도 크레딧을 태운다.

- 재시도 상한 2회 · 429·5xx·타임아웃에만 재시도 · 400 계열은 재시도하지 않음
- 잔여 크레딧이 기준 미만이면 호출하지 않고 거절
- 출력 토큰 상한 8192

### 키가 없으면

LLM 계층 빈이 아예 뜨지 않는다. **애플리케이션은 정상 기동한다.**
소비처가 `Optional<LlmChatPort>` 로 받아 없으면 503 을 준다.
