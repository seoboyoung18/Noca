- 단점
    - 정비소 답변을 받기까지 시간 소요
    - 수리 방법이 합리적인지 소비자가 이해하기 어렵기 때문에 여러 곳 비교 분석 필요

# 서비스 방향성 재고

### Point

- 사용자가 우리 서비스를 통해 가격을 알아냈다고 하더라도, 그 가격에 맞게 정비해주는 정비소를 찾아야 한다. 그럼 처음부터 카닥으로 여러 업체 견적 받는 게 더 편함
- **가격을 알려주는 서비스가 아니라 견적을 검증하는 서비스**로 가기

<aside>

**"AI가 예상 견적을 알려준다"보다 "견적을 받아왔는데 이게 적정한지 확인한다"를 메인 시나리오로 잡는 것**이 더 차별성이 있음

### 사용 시나리오

사용자가 이미 견적을 받았다고 가정

`정비소 견적 73만원`→ 견적서 촬영 → 차량 파손사진 분석 → 유사 전문가 판정 사례 검색 → 예상 수리방법 비교 → 가격 Reference와 비교

결과 표시

> 
> 
> 유사 파손: 판금+도장 사례가 많음
> 
> 받은 견적: 펜더 교환+도장
> 
> **수리 방식에 차이가 있습니다.**
> 
> 정비업체에 "교환이 필요한 이유"를 확인해보세요.

# 핵심 기능

1. **차량 파손 분석**
    - 사진 촬영 → 차종·파손 부위·손상 특징 분석
2. **유사 수리 사례 검색**
    - 대규모 과거 수리 데이터에서 유사 파손 Top-K 검색
    - 실제 수리 사진·수리 내역 제공
3. **예상 수리비 범위 제공**
    - 유사 사례 기반 평균/중앙값/비용 분포 제공
    - 과거 비용은 현재 시점에 맞게 ✅**가격 보정**
4. **수리 방식 비교**
    - 유사 사례의 ✅`복원수리 vs 부품교환` 비율 및 각각의 비용 비교
        - 복원 : 도장, 판금, 수리
        - 교환
    - 표준작업시간/공임 데이터 확보가 프로젝트의 추가 데이터 엔지니어링 과제
        - **가격 Reference DB :** 여러 판금·도장 업체 공개 가격표 크롤링
5. **견적서 비교·검증**
    - 받은 견적서 촬영 → 항목 추출
    - 유사 사례의 부품비·공임·작업 항목과 비교
    - 비용이 높은 항목 및 전체 비용분포상 위치 제공

## **MVP**

`AI Hub repair`+`공개된 판금·도장 가격 Reference`+`차종/부위별 가격 범위`로 예상 견적을 만들기

## **서비스 확장**

`사용자가 실제로 받은 견적서 OCR`→ 익명화→ `차종 / 부위 / repair / 지역 / 시점 / 가격` 축적 → **자체 실제 견적 DB 구축**

→ 데이터가 축적될수록 공개 가격 Reference 중심의 예상가격에서 **실제 시장 견적 기반 가격 Benchmark**로 고도화
