# 비정상 주행 Hotspot 분석 시스템

> **CCTV에서 반복되는 비정상 주행 패턴을 대규모로 분석해, 사고가 발생하기 전에 도로관리자가 우선 점검해야 할 위험구간을 찾아주는 시스템**
> 
- 기존 도로 안전관리는 사고 발생 이후 사고다발구간을 분석하고 개선하는 **사후 대응 방식**이 중심
- 사고가 발생하기 전에도 특정 구간에서 **실선 차선변경, 차선 물기, 연속 차로변경, 안전거리 미확보 등 비정상 주행이 반복적으로 발생**할 수 있음.
- **Vision AI**
    - CCTV 영상에서 Vision AI로 비정상 주행을 탐지하고, 이를 `위치·시간·행동유형·도로환경` 등의 이벤트 데이터로 변환
- **분산 처리**
    - Kafka와 Spark를 활용하여 다수 CCTV에서 발생하는 이벤트를 실시간 분산 처리하고, **교통량 대비 비정상 주행률 및 유사 도로 대비 발생 빈도**를 분석
- **서비스**
    - 특정 비정상 행동이 지속적으로 집중되는 구간을 **위험 Hotspot**으로 선정하여 도로관리자의 현장점검 우선순위로 제공
    - AI가 도로의 문제 원인을 직접 판단하는 것이 아니라, 관리자가 **노면표시, 안내표지, 차로 구조, 합류·분기 구조 등**을 우선 점검해야 할 구간을 선별하는 의사결정 지원 시스템
- **시연**
    - 여러 CCTV 영상을 스트리밍하고 `Vision AI → Kafka → Spark → Hotspot Dashboard` 과정을 실시간으로 보여주며, 기존 사고 기반 관리와 달리 **사고 이전의 반복적인 위험행동을 이용한 선제 관리**를 보여줌.

# 멀티모달 AI와 빅데이터 분산처리 기반 배터리 열폭주 조기예측 시스템

## 아이디어 개요

- 최근 전기차 등 리튬이온 배터리의 화재, 안전 문제가 계속 이슈가 되고 있음
- 열화상 이미지와 온도, 전압, 가스 등의 센서 데이터를 함께 분석해 배터리 열폭주를 미리 예측하고 선제적으로 대응하는 시스템
    - 기존에도 온도나 전압 등을 이용해 배터리 이상을 감지하지만, 열폭주는 빠르게 진행되기 때문에 위험을 조금이라도 일찍 예측해서 대응 시간을 확보하는 것이 중요
- 단순히 현재 열폭주 여부를 판단하는 게 아닌, 시간에 따른 열화상 변화와 여러 센서의 변화를 함께 분석해서 앞으로 위험 단계에 진입할지를 예측하는 방향
- 멀티모달 AI
    - AI Hub에 열화상 이미지와 센서 데이터, 열폭주 단계가 시간 별로 연결된 데이터셋을 활용하여 원천데이터부터 직접 전처리하고 멀티모달 AI 구현
- 빅데이터 분산처리
    - 실제 대규모 배터리 환경을 가정해, 공개 데이터가 실시간으로 발생하는 것처럼 재현하고 분산 처리하는 방식으로 활용
- 시연
    - 실제 냉각장치 대신 간단한 시뮬레이터를 활용해서 기존의 단일 센서 기반 대응과 멀티모달 AI 조기예측 기반 선제 대응을 비교하고, 조기예측으로 확보한 시간이 실제 대응에 어떤 차이를 만드는 지 입증

# **~~SMT 품질 데이터 통합 분석 및 공정 점검 지원 시스템 → 비전AI만으로 품질 이상 판단 어려움~~**

- **SMT(Surface Mount Technology)**: PCB 기판 위에 반도체 칩·저항·커패시터 등의 전자부품을 자동으로 실장하고 납땜하는 제조 공정

## 아이디어 개요

> SMT 검사 이미지와 공정 센서 데이터를 통합 분석하고, 현재 품질 이상과 과거 생산 이력을 비교하여 반복적으로 차이를 보이는 공정 Feature를 엔지니어의 점검 우선순위로 제공하는 시스템
> 
- 기존 AOI/SPI는 **제품의 불량을 검출·분류**할 수 있지만, 불량 발생 후 **어떤 공정조건 때문에 문제가 발생했는지 확인하는 과정**은 별도로 필요
- 누적된 불량 이미지와 공정 데이터를 함께 분석하여 **불량과 함께 반복적으로 이상을 보이는 공정 Feature를 찾아 점검 범위를 좁히는 것**이 목표

## 서비스 및 시연

- **서비스**
    - SMT 검사에서 수집된 현재 불량 이미지를 입력
    - Vision AI로 **시각적으로 유사한 과거 불량 사례 Top-K 검색**
    - 유사 사례와 연결된 `온도·습도·진동·가속도·소음 등`의 센서 데이터를 정상 생산 데이터와 비교
    - 반복적으로 큰 차이를 보이는 Feature를 **우선 점검 공정조건**으로 Ranking
    - 실제 Root Cause를 단정하지 않고 엔지니어의 **원인 탐색 범위를 축소**
- **시연**
    - `불량 이미지 → Visual Retrieval → 유사 불량 사례 → 공정 데이터 분석 → 이상 Feature Ranking → Dashboard`
    - 현재 불량과 유사한 과거 사례 및 정상 대비 공정 Feature 차이를 함께 시각화

## 기술

- **Vision AI**
    - SMT 불량 이미지의 형태·위치·분포 등의 시각적 특징을 Embedding으로 변환
    - Vector DB에서 **시각적으로 유사한 과거 불량 사례 Top-K 검색**
    - 이미지를 단순 불량 분류가 아니라 **관련 과거 생산 이력을 찾기 위한 Visual Query**로 활용
- **공정 데이터 분석**
    - 유사 불량 발생 당시의 센서 데이터와 정상 생산 데이터를 비교
    - Feature별 통계적 차이를 분석하고 반복적으로 큰 차이를 보이는 Feature를 Ranking
    - `동일 불량 Class 전체`와 `시각적으로 유사한 불량 집단`을 비교하여 Visual Retrieval이 공정조건 탐색에 실제로 도움이 되는지도 검증
- **분산 처리**
    - 실제 생산환경에서 장기간 누적되는 대규모 `검사 이미지 + 센서 + 검사 결과`를 Spark로 분산 처리
    - 이미지·센서 데이터 Join, Embedding 생성, 정상/불량 집단 통계 분석 등을 병렬화
    - 데이터 규모와 Worker 수에 따른 **처리시간·Throughput·Speed-up**을 비교하여 단일 처리 대비 확장성 검증

## 고려 사항

- **원인 해석의 한계**: 특정 Line의 품질 이상과 함께 특정 센서 Feature가 변화하더라도 해당 Feature가 실제 불량의 원인이라고 단정할 수 없음. 따라서 **Root Cause 자동 판정이 아니라 엔지니어의 점검 우선순위 제공**으로 범위를 설정
- **Retrieval 유효성**: 시각적으로 유사한 불량이 실제로 유사한 공정 Feature 패턴을 가지는지 실험적 검증 필요
- **분산처리 당위성**: 공개 데이터 규모 자체보다는 실제 생산환경에서 장기간 누적되는 이미지·센서 이력의 대규모 분석을 전제로 하고, 데이터 규모·Worker 수에 따른 성능 향상을 정량적으로 검증
