## 1. 가축 이상징후 조기감지 · 스마트 축사 관제

### 아이디어 개요

소·돼지 행동 영상과 축사 환경 센서(온습도·암모니아) 시계열을 결합해 기립불능·발정·질병 징후를 조기 감지하는 멀티모달 관제 시스템. 축사 여러 동 × 카메라·센서 다수에서 데이터가 계속 발생하는 구조라 분산 처리와 자연스럽게 맞물린다.

**장점**

- '조기 감지로 대응 시간 확보'라는 명확한 가치 스토리
- 농가 인력난이라는 뚜렷한 문제의식
- 영상 + 센서 멀티모달 구성으로 트랙 취지(빅데이터 분산 + AI)에 부합

**주의**

- 축산 도메인 이해 비용이 큼
- 실시간 소스가 없어 replay 계층 필요
- 행동 라벨 종류 등 데이터 구성 확인이 선행되어야 함
- 축산 환경(센서) 데이터 확보 불확실

### 활용 데이터

- AI Hub 가축 행동 영상 — [dataSetSn=145](https://aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&dataSetSn=145)
- 스마트팜코리아 빅데이터 플랫폼 — [smartfarmkorea.net](https://www.smartfarmkorea.net/) (축산 데이터 제공 여부 확인 필요)

### 검토 결과

축사 환경(센서) 데이터는 AI Hub에서 검색해도 확인되지 않았고, 발표장에서 시연을 재현할 방법이 없어 **후순위로 정리**.

## 2. 이상행동 탐지 · 지능형 CCTV 관제

### 아이디어 개요

AI Hub 이상행동 CCTV 영상(폭행·쓰러짐·배회·침입 등 10여 클래스)으로 행동 탐지 모델을 학습하고, 다수 카메라에서 발생한 이상 이벤트를 분산 집계하는 관제 시스템. 영상 원본이 아니라 **탐지 이벤트 위주로 분산 처리**해 6주 범위에 맞게 규모를 조절하는 것이 핵심 설계.

**장점**

- 규모와 라벨이 잘 갖춰진 이 트랙의 정석 데이터
- 물류 안전관제 주제와 구조가 같아 아키텍처 논의를 재활용하기 쉬움

**주의**

- 원본이 수 TB급 — 클래스를 2~3개(쓰러짐·배회)로 축소 필수
- 실시간 소스가 없어 스트림 재생(replay) 계층 설계 필요
- 데이터 구성 확인 필요

### 활용 데이터

- AI Hub 이상행동 CCTV 영상 (실외·공공장소) — [dataSetSn=171](https://aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&dataSetSn=171)
- 실내 사람 이상행동 데이터 (실내 시나리오·도난 탐지 확장용) — [dataSetSn=71550](https://aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&dataSetSn=71550)

### 검토 결과

클래스를 2~3개로 축소하면 시연이 가능하다고 판단해 **검토 대상으로 유지**. 이후 주제 재평가에서도 CCTV 이상행동 안전 관제(SafeZone)로 후보 목록에 포함되었다.

## 3. AI 콜센터 실시간 상담 지원 및 분산 분석 플랫폼

### 아이디어 개요

콜센터에 유입되는 상담 음성을 실시간으로 텍스트 변환(STT)해 상담원에게는 **응대 중 실시간 지원**(유사 상담 사례·답변 초안·감정 경고)을 제공하고, 관리자에게는 **누적 상담의 분산 분석 결과**(이슈 급증 감지·유형별 추이·상담 품질 지표)를 제공하는 플랫폼. 상담 1건이 들어올 때마다 STT → 정제 → 임베딩 → 유사 사례 검색 → 요약·분류가 이어지고, 그 결과가 다시 전체 통계로 집계된다.

**분산 정당성 4기준 평가**

| 기준 | 충족 방식 |
| --- | --- |
| ① 유입이 처리 용량 초과 | 상담원 수만큼 통화가 **동시에** 발생, 피크 시간대 집중 |
| ② 무거운 독립 연산 | 통화 1건당 STT + 임베딩 + 요약, 통화 간 의존성 없음 |
| ③ Backfill | 과거 상담 아카이브 재처리, 모델 교체 시 전량 재임베딩 |
| ④ Fan-out | 상담 1건이 실시간 지원·품질 평가·이슈 집계·검색 인덱스로 분기 |

**장점**

- 분산 정당성이 4기준 모두에서 명확 — 유입 자체가 동시다발적이라 분산 구조가 억지스럽지 않음
- 실시간 경로(상담 지원)와 배치 경로(누적 분석)가 자연스럽게 공존해 아키텍처 설명이 깔끔
- 음성 → 텍스트 → 임베딩 → 검색으로 단계가 뚜렷해 역할 분담이 쉬움
- 도메인 이해 비용이 낮음 (차량 정비·축산과 달리 별도 전문 지식 불필요)
- "상담원을 돕는다"는 사용자 가치가 직관적이고 시연 시나리오를 만들기 쉬움

**주의**

- 실시간 소스가 없어 녹취 음성을 스트림처럼 재생하는 **replay 계층 설계 필수** (1·2번 주제와 공통 과제)
- **STT 정확도가 전체 품질을 좌우** — 한국어 상담 음성은 발화 겹침·잡음·구어체가 많아 난도 있음
- 화자 분리(상담원 vs 고객)·전사 라벨 포함 여부 확인 선행 필요
- 상담 내용에 이름·전화번호 등 개인정보 포함 가능 — 비식별 처리 필요
- 실시간 지원의 응답 지연 목표를 무리하게 잡지 말 것 (통화 중 수 초 내 수준으로 한정)

**데이터 판단 (2026-08-27 AI-Hub 직접 확인)**

- **상담 음성(100GB)** 과 **민원 질의-응답(20.9GB)** 이 중심축. 둘 다 오디오+텍스트 구성이고 바로 다운로드된다. 특히 민원 질의-응답은 태그에 **상담내용 요약·상담카테고리 자동분류**가 명시돼 있어 우리 기능(요약·분류)과 라벨이 직접 대응할 가능성이 높다.
- **민간분야 고객 상담 데이터(71616)** 는 **안심존(온라인)** 데이터다. 지정 환경에서만 분석 가능하고 원본 반출이 제한될 수 있어 **파이프라인에 직접 태우기 어렵다.** 참고·검증용으로 두는 것이 안전하다.
- 설계 전제는 **"다운로드 가능한 음성 데이터 중심 + 자체 STT로 텍스트 생성"** 으로 잡는다. STT 자체가 GPU가 필요한 무거운 연산이라 분산 정당성 ②를 강화한다.

**W1 확인 항목**

1. 화자 분리·전사(transcript) 라벨 포함 여부 — 있으면 STT 성능 평가 기준으로 활용, 없으면 검증 방법 별도 마련
2. 상담 유형·감정 라벨 존재 여부 — 없으면 분류·감정 분석은 규칙 또는 사전학습 모델로 대체
3. 샘플 데이터로 음성 품질(잡음·발화 겹침) 확인
4. 한국어 STT 모델 선택 및 GPU 처리량 벤치마크 (1시간 음성 처리 소요 시간 → 배치 창 역산)

### 검토 결과

주제 재평가에서 **우선 후보(CallInsight)** 로 선정. 1·2번 주제가 공통으로 안고 있던 "실시간 소스 없음" 문제는 동일하게 남지만, **유입의 동시다발성**이라는 분산 정당성을 데이터 구조 자체로 확보한다는 점에서 앞선 두 주제보다 강하다.

## 정리

세 아이디어 모두 **"계속 발생하는 데이터를 분산 집계해 의미 있는 신호를 뽑아낸다"**는 같은 문제 구조를 갖는다. 차이는 데이터 확보 가능성과 분산의 필연성이었고, 이 기준들이 이후 팀의 주제 평가 기준을 세우는 출발점이 되었다.

- 데이터가 실제로 존재하는가 (링크·규모·라벨을 직접 확인)
- 6주 안에 범위를 줄일 수 있는가 (원본 전체가 아닌 이벤트·단위 처리)
- 발표장에서 시연으로 보여줄 수 있는가
- **분산이 설계상 들어갈 수 있는가** (유입 초과 · 무거운 독립 연산 · Backfill · Fan-out)

1·2번은 앞의 세 기준으로 걸러졌고, 3번은 네 번째 기준까지 충족해 우선 후보로 올라갔다.
