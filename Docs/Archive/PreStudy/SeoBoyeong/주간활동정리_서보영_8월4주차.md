# 주간 활동 정리 — 8월 4주차

**서보영** · SSAFY 15기 3반 A307 · 특화 프로젝트(빅데이터 분산)

---

## 1. 빅데이터 분산 기술 학습

특화 트랙의 기반 기술을 학습하고, 각 기술이 프로젝트 구조상 어디에 위치하는지 정리했다.

| 기술 | 역할 |
| --- | --- |
| Hadoop (HDFS) | 대용량 원본 데이터 분산 저장 |
| MapReduce | 배치 집계의 기본 모델, Spark와의 성능 비교 기준선 |
| Spark | 분산 전처리·집계·스트리밍 처리 |
| Kafka | 이벤트 스트림 큐, 서비스와 처리 계층의 경계 |

단순 개념 학습에 그치지 않고 "우리 서비스에서 이 기술이 왜 필요한가"를 기준으로 정리해, 이후 주제 평가와 아키텍처 설계의 판단 근거로 사용했다.

## 2. 프로젝트 주제 탐색 및 정리

여러 후보 주제를 발굴하고 데이터 확보 가능성·시연 가능성 기준으로 비교했다.

- 찾은 주제 : 이상행동 탐지 · 지능형 CCTV 관제, 가축 이상징후 조기감지 · 스마트 축사 관제, AI 콜센터 실시간 상담 지원 및 분산 분석 플랫폼 등
- AI-Hub 데이터셋 링크를 직접 확인해 규모·형식·적합성을 검증
- 노션 **주제 아이디어** 정리 및 1차·2차 기획 미팅 반영

주제 평가 기준을 **분산 정당성 4가지**(① 유입량 초과 ② 무거운 독립 연산 ③ Backfill ④ Fan-out)를 토대로 주제 후보들을 재평가했다.
현재 주제에 대해 더 탐색하고 있는 중입니다.

## 3. 기획 고도화

- 선정 주제를 **차량 파손 AI 수리 견적** 방향으로 구체화하고 마스터 문서 팀원들과 함께 작성
- 핵심 설계 결정: 수리 **비용** 직접 예측이 아니라, AI는 **손상 판정**까지 / 비용은 **공식 출처 기반 계산**으로 분리
- 비용 산정에 쓸 데이터 출처를 직접 확인 (부품가·표준정비시간·시간당 공임 / 온라인 가격 API 가용성 포함)
- 기능을 **MVP · SUB · Extra** 3단계로 구분하고 우선순위 팀 회의를 통해 정리
- 저장소 구성 정리: PostgreSQL(메인) / 오브젝트 스토리지(이미지·PDF) / HDFS+Spark(대용량 이력·학습 데이터) / Redis(캐시·상태) 다만 아직 확정은 아님

## 4. 요구사항 명세서

프로젝트 설계 문서에서 **요구사항 명세서 초안을 뽑아 고도화를 진행**했다.

- 팀 공통 양식(대분류–중분류–소분류–세분류 계층) 기준으로 요구사항 명세서 초안 작성
- 회의에서 나온 기능 목록을 세분류 단위로 분해하고, 요구사항을 서술형 문장으로 정리
- 중요도(상·중·하)를 MVP/SUB/Extra에 대응시켜 배분
- 외부 API 제약·보류 항목은 비고에 명시해 이후 판단 근거로 남기고 필요치 않은 명세들은 팀 회의를 통해 정리 및 고도화

## 5. 데이터셋 탐색 및 검증

주제 확정 전에 데이터가 실제로 쓸 수 있는 상태인지 확인하기 위해 EDA를 수행했다.

- 라벨 파일 전수 파싱으로 이미지·견적서 규모와 조인 가능 비율 확인

## 6. 프로토타입 사이트 제작

주제별 서비스 형태를 말로만 논의하지 않고, 실제 동작하는 임시 웹페이지로 만들어 확인했다.

- 후보 주제를 각각 서비스 화면으로 구현해 사용자 흐름과 기능 구성을 검증
- 기획 단계에서 "이 서비스가 실제로 어떤 모습인가"를 팀과 공유하는 데 활용
