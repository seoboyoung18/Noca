# 부품별 작업 동반 패턴 분석 노트

- 대상: `1.원천데이터_230126_add/TS_99. 붙임_견적서.zip` 내 **`as-*.json`(57,004건) + `sc-*.json`(68,002건) 전체 125,006건**.
- 방법: `zipfile` 스트리밍 read → UTF-8 디코딩 → `json.loads`. 압축 해제 없음. 파일 1건 처리 후 폐기, 그룹/조합 카운터만 누적. 전체 순회(그룹핑 포함) 약 40초.
- 그룹 정의: **한 사고(JSON 파일) 안에서 `작업항목 및 부품명`을 정규화한 문자열이 같은 라인들**을 하나의 "부품 그룹"으로 묶음. 그룹은 사고 내부에서만 만들어지며(사고 간에는 합치지 않음), 다른 사고의 동일 부품명은 별개 그룹으로 집계.
- 금액: `as-` 라인은 `부품가격+공임`, `sc-` 라인은 **`손해사정후.부품가격 + 손해사정후.공임`**(최종 확정액 기준으로 as-/sc-를 통일하기 위한 선택 — as-에는 전/후 구분이 없으므로 sc-도 "최종 금액" 관점인 후 값을 사용).

## 0. 그룹핑에 쓴 정규화 규칙

DATA_NOTES.md §4에서 확인된 문제(동일 부품이 "그린수가 NN%청구", "신품가 999,999", "(보수) 수용성", "(단독작업)" 등 접미사가 붙어 문자열이 갈라지는 문제)를 보정하기 위해, `작업항목 및 부품명`에 아래 순서로 정규화를 적용한 뒤 같은 결과 문자열끼리 그룹핑했다.

| 순서 | 규칙 (정규식) | 목적 |
|---|---|---|
| 1 | `그린수가\s*\d*%?\s*청구` 제거 | 보험 협의 비율 문구 제거 |
| 2 | `\d+%\s*청구` 제거 (그린수가 없이 단독으로 오는 경우) | 위와 동일 |
| 3 | `신품가` 제거 | 신품가 참고행 라벨 제거 |
| 4 | `단독작업` 제거 | billing 모드 태그 제거 |
| 5 | `수용성` 제거 | 도장 재질(수용성 도료) 태그 제거 |
| 6 | `(보수)` 제거 | 보수 도장 태그 제거 |
| 7 | 3자리 이상 숫자(콤마 포함, 예: `839,718`) 제거 | 항목명에 파묻힌 금액 제거 |
| 8 | 괄호 앞 공백 제거, 빈 괄호 제거, 중복 공백 정리, 앞뒤 공백·쉼표 제거 | 잔여 공백/구두점 정리 |

**검증 예시** (근거: `as-0000004.json`, `as-0000009.json`, `as-0000005.json`):

| 원문 | 정규화 결과 |
|---|---|
| `뒤범퍼(단독작업)` | `뒤범퍼` |
| `뒤범퍼 신품가 839,718` | `뒤범퍼` |
| `뒤범퍼(보수) 수용성` | `뒤범퍼` |
| `앞범퍼 그린수가 50%청구` | `앞범퍼` |
| `앞범퍼 신품가 487,200` | `앞범퍼` |
| `헤드램프(좌)그린수가 50%청구` | `헤드램프(좌)` |
| `헤드램프 신품가(좌)2,230,800` | `헤드램프(좌)` |
| `뒤범퍼 레일 그린수가 50%청구` | `뒤범퍼 레일` (별도 부품으로 유지 — "뒤범퍼"와 병합되지 않음, 의도된 동작) |

**알려진 한계 (추정 포함)**:
1. **원본 데이터 자체의 절단/오탈자는 그대로 남는다.** 예: `도어(앞우,자동문)(일체힌지` (닫는 괄호 없이 잘린 원본 문자열, `as-0000005.json` No.16·17)는 `도어(앞우,자동문)`(다른 라인)과 병합되지 않는다. 정규화 규칙이 원본 데이터 오류까지 복원하지는 못한다.
2. **"표면판금보수"처럼 정규화 목록에 없는 다른 수식어가 붙은 변형은 병합되지 않는다** (예: `sc-1000183.json`의 "리어펜더(좌) 표면판금보수"). 이런 케이스는 과소 병합(그룹이 더 세분화됨)으로 남는다.
3. **가장 중요한 한계 — 도장 단계 라인의 별도 명명 관행.** 전체 469,560건의 `도장` 작업 라인 중 **241,323건(51.4%)의 이름 자체에 `교환`/`판금`/`탈착`/`수리`/`오버홀` 같은 작업 단어가 이미 포함**되어 있다(예: `as-0004814.json`의 "후론트 범퍼교환", "후드판금", "리어 범퍼교환", "백도어판금" — 근거: 도장 라인 469,560건 전수 검사). 이런 이름은 정규화 규칙에서 작업 단어를 제거 대상으로 삼지 않았기 때문에(교환/판금 등을 지우면 다른 부품과 잘못 병합될 위험이 커서 보수적으로 남겨둠) 같은 부품의 **기본 손상 라인(예: "후드")과 병합되지 않고 별도 그룹으로 집계**된다. → 아래 §4의 "도장 단독 비율"은 이 명명 관행 때문에 **실제보다 과대추정되었을 가능성이 높다(추정)**. 해석 시 반드시 이 캐비엇을 함께 봐야 한다.

**산출 로직에 반영 시 주의점**
1. 부품 그룹 단위 원가를 추정할 때, 탈착·오버홀 계열처럼 자주 동반되는 조합({1/2OH, 수리, 탈착} 등)은 **개별 작업 단가를 단순 합산하는 것과 실제 조합 총액 중앙값이 다를 수 있으므로**, 가능하면 조합 단위 통계(§1)를 참조하는 것이 낫다.
2. **도장 관련 조합 통계는 이 노트의 정규화 규칙상 과소 병합되어 있다.** 도장이 실제로 다른 작업과 얼마나 자주 동반되는지 정확히 알려면, 도장 라인 이름 끝에 붙은 작업어(교환/판금/탈착/수리/오버홀)까지 제거하는 2차 정규화가 필요하다(이번 분석 범위 밖, 후속 작업으로 추정).
3. `불인정`이 포함된 조합(예: {불인정, 수리, 탈착} 804건, {불인정, 판금} 302건)은 SC_ADJUSTMENT_NOTES.md에서 확인했듯 손해사정 후 그 항목이 완전히 빠진 상태라, 그룹 총액 중앙값(46,000원/34,500원)이 다른 조합보다 낮게 나오는 것은 "저비용 작업"이 아니라 "일부 라인이 인정되지 않아 총액이 깎인 결과"일 수 있다 — 혼동하지 않아야 한다.
