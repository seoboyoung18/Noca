## C. 교환(exchange) WORK 행이 있는 그룹의 PART_PRICE / REFERENCE_PRICE 동반

- 그룹 키: `(사례 ID, 부품명 원문)` — §A/§B와 동일하게 정규화 없이 원문 완전일치 기준.
- line_type 판정은 `estimate_items.py::normalize_estimate_item`을 그대로 복제했다.
  - `REFERENCE_PRICE`(AS): `작업`이 빈 문자열이고 `new_part_price()` 정규식(`신품가(?:\s*\([^)]*\))?\s*([\d,]+)`)이 `작업항목 및 부품명`에서 매치되는 행.
  - `PART_PRICE`(SC): `작업`이 빈 문자열이고, **손해사정전** `부품가격`이 NULL이 아니며 **손해사정전** `공임`이 NULL 또는 0인 행 — 이 판정 자체는 손해사정전 값을 쓴다(라인타입 분류 로직 원문 그대로). 부품비 양수 여부·그룹 총액 계산은 문서 전체 규칙과 동일하게 **손해사정후**(`post_adjustment_part_cost`) 값을 쓴다.
  - `aggregate_case_total()`은 `estimate_service.py::_aggregate_case`를 그대로 복제해 그룹의 포함 WORK 행(part_cost+labor_cost, coating은 paint_material_cost로) + PART_PRICE 행의 부품비를 합산한다.
- ⚠️ 원문 완전일치 그룹핑이므로, 실제 DB가 쓰는 `part_code`(별도 part_name_mapping seed, 미보유) 기준 그룹과 다를 수 있다 — 아래 §C 참고 수치가 그 차이를 보여준다.
