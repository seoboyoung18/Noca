> **작성 2026-09-12** · 기준 `origin/develop` `a95eb9c`
> **대상** 인프라 담당 2인 · 2026-09-14(월) 작업용

## 0. 이 문서의 전제 — "완성되면 배포" 가 아니다

시연 당일에 처음 배포하면 **그날 처음 만나는 문제**들이 있다. 그리고 그 문제들은
**기능 완성도와 무관하다** — Dockerfile 유무, 마이그레이션 순서, 환경변수 오타, CORS 오리진.

아래 §1 의 여섯 가지 중 **기능이 완성돼야 확인 가능한 것은 하나도 없다.** 지금 전부 할 수 있다.

**백엔드는 지금 배포할 수 있다.** `a95eb9c` 기준 엔드포인트 76개가 돌고 테스트 1289건이 통과한다.
값이 안 차는 화면(금액·분석 진행)은 **빈 값으로 보일 뿐 앱은 정상 기동한다** — 어댑터가 없으면
해당 API 만 503 으로 떨어지는 구조다. **AI 서버가 아예 없어도 백엔드는 뜬다.**

막혀 있는 것은 FE 다. `frontend` 디렉터리가 저장소에 없고 랜딩 페이지(`-418`·`-419`·`-420`)도
미착수다. 그래서 순서는 이렇게 된다.

```
1. BE 단독 배포     ← 월요일 목표. 환경 문제를 미리 털어낸다
2. FE 붙이기        ← FE 착수 후. CORS 오리진 추가면 끝
3. AI 서버 배포     ← 별개. BE 는 그동안 503 으로 버틴다
```

## 3. 환경변수 — `${}` 유래 25개 + 표준 설정 덮어쓰기 6개

**성격이 다른 두 묶음이다. 합쳐서 한 숫자로 부르지 않는다.**

| 묶음 | 개수 | 무엇 | 어디 |
| --- | --- | --- | --- |
| **A. `${}` 유래** | **25** | `application.properties` 가 `${NAME:기본값}` 으로 선언한 것. 이 저장소 고유 이름이다 | §3-1 · §3-2 · §3-3 · §3-4 · §3-5 · §3-6 |
| **B. 표준 설정 덮어쓰기** | **6** | 파일에 없거나 하드코딩된 **스프링 표준 프로퍼티**를 환경변수로 덮는 것. 이름이 스프링 규약을 따른다 | §3-1-A (2) · §3-1-B (2) · §3-1-C (2) |

A는 `grep -oE '\$\{[A-Z_]+[:}]' application.properties | sort -u` 로 센 값이다(실측 25).
B는 **파일을 아무리 읽어도 안 나온다** — 그래서 빠뜨리기 쉽다. 전부 컨테이너·프록시 때문에 필요하다.

```
B 6개
  SPRING_DATASOURCE_URL                       §3-1-A   컨테이너면 항상
  SPRING_DATA_REDIS_HOST                      §3-1-A   컨테이너면 항상
  SPRINGDOC_APIDOCS_ENABLED                   §3-1-B   운영에서 끌 거면
  SPRINGDOC_SWAGGERUI_ENABLED                 §3-1-B   운영에서 끌 거면
  SERVER_FORWARD_HEADERS_STRATEGY             §3-1-C   프록시 뒤면 항상
  SERVER_SERVLET_SESSION_COOKIE_SAME_SITE     §3-1-C   다른 사이트 배치일 때만
```

**값은 여기에 적지 않는다.**

### 3-1. 없으면 앱이 안 뜬다

| 이름 | 비고 |
| --- | --- |
| `DB_USERNAME` | 기본값 없음 |
| `DB_PASSWORD` | 기본값 없음 |

### 3-1-A. 🔴 컨테이너로 띄우면 반드시 추가로 필요하다

`application.properties` 에 **주소가 하드코딩돼 있다.** 환경변수가 아니다.

```
spring.datasource.url=jdbc:postgresql://localhost:5432/a307
spring.data.redis.host=localhost
```

로컬 개발에서는 맞지만 **컨테이너 안에서 `localhost` 는 컨테이너 자신**이라 DB·Redis 에 닿지
못한다. 코드를 고칠 필요는 없다 — 스프링의 relaxed binding 으로 환경변수가 이긴다.

| 이름 | 값 예시 | 언제 |
| --- | --- | --- |
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://<DB호스트>:5432/a307` | DB 가 같은 호스트가 아닐 때 = 컨테이너면 항상 |
| `SPRING_DATA_REDIS_HOST` | `<Redis호스트>` | 같음 |

**실측으로 확인했다.** 이 둘을 주고 컨테이너를 띄우니 8.6초에 기동했다 (아래 §3-7).
빠뜨리면 `HikariPool-1 - Starting...` 에서 멈췄다가 기동 실패한다.

### 3-1-B. ⚠️ 운영에서 꺼야 하는 것 — 안 끄면 API 문서가 전부 공개된다

컨테이너 기동 로그의 경고 2건이 이것이었다. 그 외 경고는 없었다.

```
SpringDoc /v3/api-docs endpoint is enabled by default. To disable it in production, ...
SpringDoc /swagger-ui.html endpoint is enabled by default. To disable it in production, ...
```

`springdoc.api-docs.enabled=false` · `springdoc.swagger-ui.enabled=false` 를 환경변수
(`SPRINGDOC_APIDOCS_ENABLED=false` · `SPRINGDOC_SWAGGERUI_ENABLED=false`) 로 준다.

**끄기 전에 팀에 묻는다.** 심사·시연에서 Swagger 를 쓸 생각이면 끄면 안 된다.
끄지 않기로 정하면 그것도 결정이다 — 모르고 열어두는 것과 다르다.

### 3-1-C. 🔴 nginx 뒤에 두면 필요하다 — 안 하면 로그인이 깨진다

**둘 다 `application.properties` 에 없는 스프링 표준 설정이다.** 환경변수로만 준다.

| 이름 | 값 | 언제 |
| --- | --- | --- |
| `SERVER_FORWARD_HEADERS_STRATEGY` | `framework` | 리버스 프록시 뒤 = **사실상 항상** |
| `SERVER_SERVLET_SESSION_COOKIE_SAME_SITE` | `None` | FE·BE 가 **서로 다른 사이트**일 때만 |

#### 왜 첫 번째가 필요한가 — 소셜 로그인이 깨진다

```
application.properties:36
  ...kakao.redirect-uri={baseUrl}/login/oauth2/code/{registrationId}
```

`{baseUrl}` 은 스프링이 **들어온 요청에서** 만든다. `server.forward-headers-strategy` 가 없으면
기본값이 `NONE` 이라, nginx 가 TLS 를 끊고 `http://127.0.0.1:8080` 으로 넘기면 스프링이 보는
스킴은 `http`, 호스트는 내부 주소다. → 카카오·구글에 등록한 URI 와 달라져 **`redirect_uri_mismatch`**.

**nginx 쪽도 같이 해야 한다.** 하나만 하면 안 고쳐진다.

```nginx
proxy_set_header Host              $host;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-Host  $host;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
```

> 🔴 **신뢰할 수 있는 프록시 뒤에서만 켠다.** 앱이 인터넷에 직접 노출된 상태에서 켜면
> 클라이언트가 `X-Forwarded-Proto` 를 위조해 스프링을 속일 수 있다.
> 8080 을 외부에 열지 않는 것이 전제다.

#### 왜 두 번째가 필요한가 — 로그인은 되는데 API 가 전부 401

이 서비스는 JWT 가 아니라 **서버 세션 + 쿠키**(`SESSION`, Redis 저장)다.
`CookieSerializer` 설정이 없어 Spring Session 기본값 **`SameSite=Lax`** 가 적용된다.

| FE ↔ BE 배치 | 결과 |
| --- | --- |
| 같은 도메인, 경로 분리 (`/` ↔ `/api`) | 문제 없음 |
| 같은 상위 도메인의 서브도메인 | 문제 없음 |
| **서로 다른 도메인** | 🔴 로그인 직후부터 전 API 401 |
| FE `http` / BE `https` | 🔴 401 |

**증상이 고약하다.** 로그인 자체는 성공하고 리다이렉트도 잘 된다. 그 다음 호출만 전부 401이다.

#### ⚠️ 두 변수는 연결돼 있다

```
SERVER_FORWARD_HEADERS_STRATEGY=framework
        ├─→ {baseUrl} 이 외부 https 로 잡힌다        → 소셜 로그인 해결
        └─→ request.isSecure() 가 true 가 된다
                  └─→ 세션 쿠키에 Secure 가 자동으로 붙는다

SERVER_SERVLET_SESSION_COOKIE_SAME_SITE=None       → 다른 사이트 배치일 때만
```

**`Secure` 를 따로 줄 필요가 없다.** `DefaultCookieSerializer` 는 `useSecureCookie` 가
설정되지 않으면 `request.isSecure()` 를 따른다(바이트코드 확인). 첫 번째 변수가 그것까지 해결한다.

**`SameSite=None` 은 `Secure` 없이는 브라우저가 거부한다.** 즉 TLS 가 먼저 서 있어야 한다.

절차와 증상별 진단은 **`인프라 실행 교본.md` §5-7 · §5-8 · §5-9 · §6-6 · §6-7** 에 있다.

### 3-5. 🔴 CORS — 이것 하나로 전 화면이 막힌다

| 이름 | 기본 |
| --- | --- |
| `CORS_ALLOWED_ORIGINS` | `app.frontend-base-url` 을 따라감 |
| `FRONTEND_BASE_URL` | `http`(로컬) |

배포된 FE 오리진을 넣지 않으면 **모든 API 호출이 브라우저에서 차단된다.**
증상이 화면 하나가 아니라 전 화면이고, **브라우저 콘솔에만 나오고 서버 로그에는 아무것도
남지 않는다.** 원인을 찾는 데 시간이 걸린다.

`setAllowCredentials(true)` 라 `*` 를 쓸 수 없다. 오리진을 정확히 적어야 한다.

### 3-6. 나머지

`AWS_REGION`(기본 `ap-northeast-2`) · `GMS_PROVIDER`(기본 `GEMINI`) · `GMS_MODEL` ·

## 4. 월요일 분담 — 각자 EC2 한 대씩

**자르는 기준은 "준비/실행" 이 아니라 "박스" 다.**
준비/실행으로 자르면 김재원이 EC2 를 한 번도 안 만진다. **박스로 자르면 둘 다 만진다.**

| | 김재원 — **AI 박스** | 서보영 — **FE+BE 박스** |
| --- | --- | --- |
| 맡는 것 | PostgreSQL + pgvector · 마이그레이션 · 데이터 적재 | 앱 컨테이너 · nginx · TLS · 도메인 · CORS |
| 시점 | 오전 | 오후 |
| 분량 | 적다 | 많다 (시연 경로 전체) |

### 4-1. 🔴 병렬이 아니다 — 순서가 있다

**"각자 1대" 를 동시 시작으로 읽으면 월요일에 깨진다.**

BE 는 `ddl-auto=validate` 라서 **DB 가 떠 있고 스키마가 맞아야 기동 자체를 한다**(§2).
**김재원의 박스가 서보영 님 박스의 선행 조건이다.**

```
김재원 (오전)                          서보영 (오후)
  PostgreSQL 기동                        EC2·Docker·IAM      ← 선행 조건 없음. 먼저 해도 됨
  스키마 초기화                             │
  마이그레이션 적용  ──── 준비 완료 신호 ───→ 환경변수 → 빌드 → 기동
  데이터 적재                              nginx · TLS · CORS
```

### 4-2. ✅ 전제였던 "DB 를 AI 박스에 둔다" 가 확정됐다

**2026-09-14 김재원 결정. §6-1 의 권장안을 그대로 채택했다.**
이로써 위 분담이 확정 상태가 된다. 아래는 그 판단의 근거로 남긴다.

DB 를 BE 박스에 뒀다면 **김재원의 박스는 월요일에 할 일이 거의 없어졌을 것이다.**
BE 가 부르는 **자체 호스팅 AI 서버가 아직 없기 때문이다.**

```
grep -nE "^app\..*(base-url|url)=" backend/src/main/resources/application.properties
  app.frontend-base-url       (프론트)
  app.gms.base-url            https://gms.ssafy.io/gmsapi    ← SSAFY 호스팅
  app.kakao.local.base-url    https://dapi.kakao.com
  app.estimate-ocr.base-url   https://gms.ssafy.io/gmsapi    ← 같음
```

**자체 AI 를 부르는 설정이 한 줄도 없다.** `analysis/` 패키지에 HTTP 클라이언트도 없다 —
BE↔AI 연동 계약이 아직 안 열렸다. 그래서 지금 AI 박스에 올라가는 것은
**PostgreSQL 과 데이터 적재**(`pipeline/jobs/ingestion/load_search_data.py` 가 `repair_case` 125,006건)다.

→ **DB 위치를 먼저 정해야 이 분담이 확정된다**(§6-1).

### 4-3. ⚠️ 나눠지지 않는 것 — VPC · 보안그룹 · IAM

**계정 단위지 박스 단위가 아니다.** 두 사람이 동시에 고치면 서로 덮어쓴다.
특히 **두 박스 사이 5432 를 여는 규칙은 양쪽에 걸리는 일**이다.

→ **시작 전 30분에 같이 정하고, 규칙 변경은 한 사람이 몰아서 한다.**

### 4-4. 왜 이렇게 나눴나 — 원래 취지는 그대로다

김재원은 FAST 프로젝트에서 배포를 해 봤고, **팀 안에 배포를 할 줄 아는 사람이 둘이 되는 편이
낫다**는 것이 원래 취지였다. 시연 경로 전체(앱·nginx·TLS·CORS)를 서보영 님이 하므로
**그 취지는 유지된다.**

서보영 님은 미완 30건(49pt)을 들고 있고 그중 11pt 가 시연 화면 6개를 막고 있다.
그래서 **AI 박스 쪽을 김재원이 통째로 가져간다.**

### 4-5. 김재원은 옆에 있는다

박스를 나눠도 문서로 안 되는 판단이 있다.

- API 가 503 이다 → **의도된 건가, 설정이 빠진 건가.** 어댑터 8개 중 시연에 필요한 것만 안다
- 워커를 켤까 → 5개 다 켜면 GMS 크레딧을 태운다
- 앱이 안 뜬다 → 마이그레이션 순서인지 환경변수인지. 증상이 같다
- 처음 보는 스택트레이스 → 어느 도메인 코드인지 아는 사람이 빠르다

### 4-6. 예상 2~3시간

오전 준비가 끝나 있으면 오후 실행은 길지 않다. 서보영 님은 나머지 시간에 본인 작업으로 돌아간다.

### 4-7. 충돌 방지

**nginx 설정과 `docker-compose.yml` 은 한 사람만 건드린다.** 둘이 같이 만지면 덮어쓴다.
보안그룹·IAM 도 마찬가지다(§4-3).

### 왜 "백엔드 다 끝내고 배포" 가 아닌가

그렇게 잡으면 배포가 30건 뒤가 되고 **시연 직전에 첫 배포**를 하게 된다. §0 의 여섯 가지는
기능 완성도와 무관하게 지금 확인할 수 있고, 그날 처음 만나면 고칠 시간이 없다.

## 5. 배포 직후 확인

`/actuator/health` 만 보면 안 된다. **어댑터가 없어도 UP 이 뜬다.**

```bash
# 기동
curl -s localhost:8080/actuator/health

# 인증 요구 (401 이어야 정상)
curl -s -o /dev/null -w '%{http_code}\n' localhost:8080/api/vehicles/me

# 비인증 공개 (200 이어야 정상)
curl -s -o /dev/null -w '%{http_code}\n' localhost:8080/api/guides/checklist

# 503 이 나오면 그 어댑터의 환경변수가 빠진 것이다
curl -s -o /dev/null -w '%{http_code}\n' localhost:8080/api/repair-shops?latitude=37.5&longitude=127.0
```

**503 이 나오는 API 목록을 적어 두고 의도한 것인지 확인한다.** 시연에 필요 없는 것은 503 이어도 된다.

## 6. 먼저 정해야 할 것 — 월요일 시작 전 30분

### 6-1. ✅ PostgreSQL 을 어디에 두나 — **AI 서버로 결정** (2026-09-14, 김재원)

> 이 결정으로 §4 분담이 확정됐다. 아래는 왜 그렇게 정했는지의 기록이다.
> **월요일 시작 전 서보영 님에게 결정 사실을 공유한다.** 문서만 갱신하고 말로 안 하면
> 상대는 여전히 미정으로 알고 있다.

AI 쪽 파이프라인이 DB 를 **직접** 쓴다(`load_search_data.py` 가 `repair_case_image.storage_key` 를
직접 넣는다). 즉 AI 서버에서 DB 가 보여야 한다.

| | DB 를 BE 서버에 | **DB 를 AI 서버에 ← 채택** |
| --- | --- | --- |
| 대량 적재 | 네트워크 경유 | 같은 박스 |
| 사용자 API | 같은 박스 | VPC 내부 홉 (체감 없음) |
| 재배포 위험 | **DB 가 하루 수십 번 재배포되는 박스에 있다** | BE 박스는 언제든 날려도 된다 |

DB 의 가장 무거운 손님이 사용자 API 가 아니라 **적재 배치**이고,
`repair_case` 125,006건은 다시 만들기 싫은 자산이다.

### 6-1-A. 🔴 결정에 딸려오는 의무 — 추론 컨테이너에 메모리 상한을 건다

**AI 박스에 두기로 한 이상 이건 선택이 아니다.** 안 걸면 모델이 메모리를 먹다가
같은 박스의 PostgreSQL 을 끌고 내려간다. 그 순간 **BE 도 같이 죽는다** —
`ddl-auto=validate` 라 DB 가 없으면 재기동도 안 된다.

```bash
docker run --memory=4g --memory-swap=4g --cpus=2 ...
```

### 6-2. 확인 필요

- **EC2 두 대 스펙** (RAM · vCPU) — JVM 힙과 `shared_buffers` 를 계산하려면 필요하다
- **AI 서버가 GPU 인가** — GPU 면 호스트 RAM 이 DB 에 남아 6-1 추천이 더 강해진다
- **도메인·TLS 인증서** 준비 여부
