> **서버 상태** 로컬만. **`develop` 에 없다** — 아직 커밋되지 않았다 (아래 ⚠️)
> **작성 기준** 미커밋 로컬 작업본 (HEAD `6c86974` + 미추적 소스). 2026-09-05

## ⚠️ 시작하기 전에 — 지금은 화면을 "만들 수는" 있어도 "호출해 볼 수는" 없다

두 가지가 막혀 있다. **둘 다 차량 API 의 결함이 아니다.**

| # | 막힌 것 | 풀리는 시점 |
|---|---|---|
| 1 | **코드가 아직 `develop` 에 없다.** 지금 `develop` 을 받으면 `/api/vehicles` 자체가 존재하지 않는다 | 재원님 커밋·푸시 후 |
| 2 | **로그인이 아직 구현되지 않았다.** 5개 API 가 전부 인증을 요구하는데 로그인할 방법이 없어 **전부 401** | 인증(회원가입·소셜 로그인) 스토리 완료 후 |

**그래도 이 문서로 화면은 만들 수 있다.** 응답 JSON·상수표·동작 규칙이 전부 확정돼 있고, 아래 내용은 추측이 아니라 코드에서 읽거나 실제로 호출해서 확인한 것이다. **실호출 검증만 인증 스토리 이후로 미루면 된다.**

## 0. 먼저 알아야 할 것 세 가지

### 0-1. 등록 요청 본문은 `modelId` + `modelYear` **두 개가 전부**다

화면에는 제조사·차량명·차량 유형·차급이 다 보이지만, **서버로 가는 건 두 개뿐**이다.

```json
POST /api/vehicles
{ "modelId": 14, "modelYear": 2021 }
```

제조사·유형·차급은 **모델을 고르는 순간 결정된다.** 사용자가 따로 고르는 값이 아니고, 보내도 서버가 쓰지 않는다.

> **FE 가 가장 많이 오해하는 지점이다.** 등록 폼의 상태는 4~5개지만 payload 는 2개다.

### 0-2. 5개 API 전부 인증이 필요하다 — 지금은 예외 없이 401

`permitAll` 목록에 `/api/vehicles` 도 `/api/vehicle-models` 도 **없다.** 그리고 로그인 수단이 아직 없다.
**401 응답의 본문 모양이 다른 API 와 다르다** — 2-3 을 반드시 읽을 것.

### 0-3. 목록에 없는 차량은 **등록할 수 없다** — 직접 입력 UI 를 만들지 말 것

`vehicle.model_id` 가 `NOT NULL` + `vehicle_model` FK 다. 마스터(현재 **51종**)에 없는 차량은 **DB 구조상 등록이 불가능**하다.
Story 본문의 *"목록에 없는 차량은 직접 입력 · 기타로 분류"* 는 **구현되지 않았고, 지금 구조로는 구현할 수 없다.**

### 1-1. GET `/api/vehicle-models` — 모델 목록 (드롭다운용)

**요청** — 파라미터 없음. **제조사 필터 파라미터가 없다.** 페이지네이션도 없다. 활성 모델 **51종 전체**가 한 번에 온다(약 5KB).

**200**

```json
{
  "data": {
    "vehicleModels": [
      { "modelId": 1,  "manufacturer": "현대", "modelName": "캐스퍼", "vehicleType": "SUV",   "carClass": "CityCar" },
      { "modelId": 14, "manufacturer": "현대", "modelName": "아반떼", "vehicleType": "SEDAN", "carClass": "Mid-size" },
      { "modelId": 39, "manufacturer": "현대", "modelName": "포터2",  "vehicleType": "TRUCK", "carClass": "Full-size" }
    ]
  }
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `modelId` | number | 등록 요청에 그대로 보낼 값 |
| `manufacturer` | string | 브랜드 문자열 **12종**. 그룹 정보는 없다 → 3-1 로 FE 가 묶는다 |
| `modelName` | string | |
| `vehicleType` | string | `SEDAN` `SUV` `VAN` `TRUCK` → 3-3 |
| `carClass` | string | `CityCar` `Compact` `Mid-size` `Full-size` → 3-2 |

- `isActive` 는 **응답에 없다.** 활성인 것만 내려오므로 필요 없다
- **서버가 준 순서를 쓰지 말 것** → 3-4

**에러** — 401 뿐이다. 파라미터가 없어 400 이 날 일이 없다.

### 1-2. POST `/api/vehicles` — 차량 등록

**요청**

```json
{ "modelId": 14, "modelYear": 2021 }
```

| 필드 | 타입 | 필수 | 제약 |
|---|---|:---:|---|
| `modelId` | number | ✅ | 활성 모델의 id. 없는 값이면 400 |
| `modelYear` | number | ✅ | **1980 ~ 2100** (경계 포함) |

**201 Created**

```json
{
  "data": {
    "vehicleId": 1,
    "modelId": 14,
    "manufacturer": "현대",
    "modelName": "아반떼",
    "vehicleType": "SEDAN",
    "carClass": "Mid-size",
    "modelYear": 2021
  }
}
```

> **200 이 아니라 201 이다.** `res.ok` 로 보면 문제없지만 `status === 200` 으로 분기하면 깨진다.
> 응답에 모델 정보가 다 들어 있어 **등록 직후 재조회가 필요 없다.**

**에러**

| 상황 | 상태 | `error.code` | `error.message` |
|---|:---:|---|---|
| `modelId` 누락 | 400 | `INVALID_REQUEST` | `modelId: 필수입니다.` |
| `modelYear` 누락 | 400 | `INVALID_REQUEST` | `modelYear: 필수입니다.` |
| 연식 1979 이하 | 400 | `INVALID_REQUEST` | `modelYear: 1980 이상이어야 합니다.` |
| 연식 2101 이상 | 400 | `INVALID_REQUEST` | `modelYear: 2100 이하여야 합니다.` |
| 없는/비활성 `modelId` | 400 | `INVALID_REQUEST` | `등록할 수 없는 차량 모델입니다.` |
| 본문이 JSON 이 아님 | 400 | `INVALID_REQUEST` | `요청 본문을 해석할 수 없습니다.` |
| 미인증 | 401 | — | **2-3 참고 (봉투가 다르다)** |

> ⚠️ **`error.message` 를 파싱하지 말 것.** 검증 오류가 두 개면 `, ` 로 이어 붙고(`modelId: 필수입니다., modelYear: 필수입니다.`) 순서도 보장되지 않는다. **분기는 `error.code` 로, 표시는 `error.message` 를 그대로.**

### 1-4. PATCH `/api/vehicles/{vehicleId}` — 연식 수정

**요청** — **연식만 바꿀 수 있다.**

```json
{ "modelYear": 2022 }
```

| 필드 | 타입 | 필수 | 제약 |
|---|---|:---:|---|
| `modelYear` | number | ✅ | 1980 ~ 2100 |
| `modelId` | — | ❌ | **보내면 400.** 조용히 무시하지 않는다 |

> **차량 모델은 수정할 수 없다.** 차급이 바뀌면 기존 견적의 `ref_condition` 과 어긋나기 때문이다.
> → **수정 화면에서 모델 드롭다운은 비활성**이어야 한다. 모델을 바꾸려면 **삭제 후 재등록**이다.
> ⚠️ 폼 상태를 통째로 PATCH 하면 `modelId` 가 딸려 가 **400 이 난다.** `modelYear` 만 담을 것.

**200** — 1-2 와 같은 모양(수정된 `modelYear` 반영).

**에러**

| 상황 | 상태 | `error.code` | `error.message` |
|---|:---:|---|---|
| `modelYear` 누락 | 400 | `INVALID_REQUEST` | `modelYear: 필수입니다.` |
| 연식 범위 밖 | 400 | `INVALID_REQUEST` | `modelYear: 1980 이상이어야 합니다.` 등 |
| **`modelId` 를 보냄** | 400 | `INVALID_REQUEST` | `modelId: 차량 모델은 변경할 수 없습니다.` |
| `{vehicleId}` 가 숫자가 아님 | 400 | `INVALID_REQUEST` | `vehicleId 값이 올바르지 않습니다.` |
| **없는 차량 · 남의 차량 · 삭제된 차량** | 404 | `NOT_FOUND` | `차량을 찾을 수 없습니다.` |
| 미인증 | 401 | — | 2-3 |

### 1-5. DELETE `/api/vehicles/{vehicleId}` — 차량 삭제

**204 No Content · 본문 없음.** `res.json()` 을 호출하면 파싱 에러가 난다.

- **소프트 삭제**다. 행은 남고 목록에서만 사라진다 → **사고 이력의 차종은 그대로 보인다**
- **사고 이력이 있어도 204.** 409 는 없다
- **멱등하다.** 이미 삭제된 차량을 다시 지워도 **204** (404 아님) → 중복 클릭 방어 로직이 없어도 안전

**에러**

| 상황 | 상태 | `error.code` |
|---|:---:|---|
| 없는 차량 · **남의 차량** | 404 | `NOT_FOUND` |
| `{vehicleId}` 가 숫자가 아님 | 400 | `INVALID_REQUEST` |
| 미인증 | 401 | 2-3 |

> 삭제 확인 모달에 **"사고 이력은 그대로 남습니다"** 를 안내하는 편이 좋다.

## 2. 공통 응답 봉투와 에러

### 2-1. 성공 봉투 — 항상 `data` 로 감싼다

```json
{ "data": { ... } }
```

**배열이 바로 오지 않는다.** 목록도 한 번 더 감싸여 있다.

| API | 꺼내는 경로 |
|---|---|
| 모델 목록 | `res.data.vehicleModels` |
| 내 차량 목록 | `res.data.vehicles` |
| 등록 · 수정 | `res.data` (객체) |
| 삭제 | 본문 없음 |

### 2-2. 에러 봉투 — 400 · 404

```json
{ "error": { "code": "NOT_FOUND", "message": "차량을 찾을 수 없습니다." } }
```

`code` 는 400 `INVALID_REQUEST` · 404 `NOT_FOUND` · 500 `INTERNAL_ERROR` 를 쓴다.
**차량 API 에서 403 · 409 는 나오지 않는다** (남의 차량은 404, 삭제 충돌은 없음).

### 2-3. ★ 401 만 봉투가 다르다 — 실측 확인함

**401 은 위 봉투를 쓰지 않는다.** 시큐리티가 서블릿 컨테이너 기본 오류로 응답하기 때문에 공통 예외 처리기를 거치지 않는다.

**실제로 호출해서 받은 본문이다(추측 아님):**

```
$ curl -i http://localhost:18080/api/vehicles/me

HTTP/1.1 401
Content-Type: application/json
Set-Cookie: SESSION=...; Path=/; HttpOnly; SameSite=Lax

{"timestamp":"2026-09-05T10:56:11.419Z","status":401,"error":"Unauthorized","path":"/api/vehicles/me"}
```

⚠️ **`error` 가 객체가 아니라 문자열이다.**

| | 400 · 404 | **401** |
|---|---|---|
| `error` 의 타입 | **객체** `{ code, message }` | **문자열** `"Unauthorized"` |
| `error.code` | `"NOT_FOUND"` | **`undefined`** |
| 추가 필드 | 없음 | `timestamp` `status` `path` |

**에러 처리를 한 군데로 짜면 401 에서만 깨진다.** `err.error.code` 를 읽는 코드는 401 에서 `undefined` 를 받고, `err.error.message` 도 `undefined` 다. 세션 만료는 가장 자주 일어나는 에러라 반드시 밟게 된다.

→ **401 은 본문을 보지 말고 `status === 401` 로만 분기할 것.** (로그인 화면으로 보내면 된다.)

```js
if (res.status === 401) { goToLogin(); return; }        // 본문 파싱 금지
const body = await res.json();
if (!res.ok) showError(body.error.message);             // 400 · 404 · 500
```

### 2-4. ⚠️ 없는 경로가 404 가 아니라 **500** 으로 온다 — 서버 결함(수정 예정)

```
$ curl http://localhost:18080/api/guides/nope
{"error":{"code":"INTERNAL_ERROR","message":"서버 내부 오류가 발생했습니다."}}   [HTTP 500]
```

공통 예외 처리의 catch-all 이 "핸들러 없음"까지 삼켜서 500 으로 바꾼다. **차량 API 만의 문제가 아니라 전 API 공통이다.**

→ **FE 에서 500 이 나오면 서버 장애를 의심하기 전에 URL 오타를 먼저 확인할 것.** 서버 수정 예정이며, 고쳐지면 404 `NOT_FOUND` 로 바뀐다.

### 2-5. 인증 방식과 CORS — 실측 확인함

- **서버 세션 방식**이다. JWT 가 아니다. 세션 ID 는 `SESSION` **HttpOnly 쿠키**로 오간다
- → **모든 요청에 `credentials: 'include'` (axios 는 `withCredentials: true`) 가 필요하다.** 빼면 인증이 붙은 뒤에도 계속 401 이다
- CORS 는 **`http://localhost:5173` 하나만** 허용한다. `allowCredentials: true`, 프리플라이트 200 확인
- → **FE 개발 서버를 반드시 5173 포트로 띄울 것.** 포트가 다르면 CORS 에서 막힌다
- 401 응답에도 `SESSION` 쿠키가 내려온다. **로그인된 것이 아니다** — 빈 세션일 뿐이니 쿠키 유무로 로그인 여부를 판단하지 말 것

## 3. 상수표 — 그대로 복사해 쓸 것

서버가 내려주지 않는 값이다. **FE 가 지어내면 화면마다 달라진다.**

### 3-1. 제조사 → 5그룹 (2026-09-05 확정)

서버는 브랜드 문자열 12종만 준다. 아래 매핑은 **시드 데이터의 실제 값과 철자를 1:1 대조해 확인**했다(12종 전부 일치, 앞뒤 공백 없음).

| 그룹 | `manufacturer` 값 |
|---|---|
| **현대** | `현대` |
| **기아** | `기아` |
| **제네시스** | `제네시스` |
| **기타 국산** | `KG모빌리티` · `르노코리아` · `쉐보레` |
| **수입** | `BMW` · `벤츠` · `아우디` · `도요타` · `폭스바겐` · `혼다` |

```js
// 배열 순서가 곧 드롭다운 표시 순서다 (3-4)
export const MANUFACTURER_GROUPS = [
  { group: '현대',      brands: ['현대'] },
  { group: '기아',      brands: ['기아'] },
  { group: '제네시스',  brands: ['제네시스'] },
  { group: '기타 국산', brands: ['KG모빌리티', '르노코리아', '쉐보레'] },
  { group: '수입',      brands: ['BMW', '벤츠', '아우디', '도요타', '폭스바겐', '혼다'] },
];
```

⚠️ **철자에 주의.** `벤츠` 다 — `메르세데스-벤츠` 가 아니다. `KG모빌리티`(공백 없음) · `르노코리아`(공백 없음) · `도요타` · `폭스바겐`.
표에 없는 `manufacturer` 값이 응답에 오면 **그 브랜드만 화면에서 사라진다.** 매칭에 실패하면 임의로 한쪽 그룹에 넣지 말고 **눈에 띄게 처리**할 것(콘솔 경고 등).

### 3-2. 차급 코드 → 한글 라벨

응답의 `carClass` 는 영어 코드다. 사용자에게 그대로 보여줄 수 없다.

| 코드 | 한글 라벨 |
|---|---|
| `CityCar` | 경형 |
| `Compact` | 소형 |
| `Mid-size` | 중형 |

### 3-4. 정렬 순서 — ★ 서버가 준 순서를 그대로 쓰지 말 것

**서버 응답의 정렬 순서에는 현재 의미가 없다.** DB collation 이 `en_US.utf8` 이라 한글이 가나다순으로 정렬되지 않고 **사실상 글자 수 순**이 된다. 실측:

```
제조사   기아·벤츠·현대·혼다(2자) → 도요타·쉐보레·아우디(3자) → 제네시스·폭스바겐(4자)
        → 르노코리아(5자) → BMW·KG모빌리티(ASCII 는 맨 뒤)

모델명   현대 11종이 이 순서로 온다:
        베뉴 코나 투싼 → 그랜저 싼타페 쏘나타 아반떼 캐스퍼 → 스타리아 팰리세이드 → 포터2
```

**`manufacturer` 와 `modelName` 둘 다 해당된다.** 드롭다운 두 개가 모두 영향을 받는다.

| | FE 가 할 일 |
|---|---|
| **제조사** | **FE 가 3-1 의 5그룹 순서로 정렬한다.** 요구사항 순서(현대·기아·제네시스·기타 국산·수입)는 가나다순도 아니므로 서버가 대신해 줄 수 없다 |
| **모델명** | **당분간 FE 가 가나다순(`localeCompare('ko')`)으로 정렬한다.** 서버가 `ko-x-icu` 컬레이션으로 고칠 예정(별도 Task)이며, 고쳐지면 서버 순서를 그대로 써도 된다 |

```js
// 모델명 — 서버 수정 전까지 필요
models.sort((a, b) => a.modelName.localeCompare(b.modelName, 'ko'));
```

> 서버 수정이 반영되면 이 문서를 갱신한다. 그때까지는 **둘 다 FE 가 정렬**해야 한다.

### 3-5. 분석 미지원 차종 판별 — `vehicleType` 이 `VAN` 또는 `TRUCK`

```js
const isUnsupported = (v) => v.vehicleType === 'VAN' || v.vehicleType === 'TRUCK';
```

해당 차종은 **4종뿐**이다.

| `modelId` | 제조사 | 모델명 | `vehicleType` |
|---:|---|---|---|
| 38 | 현대 | 스타리아 | `VAN` |
| 44 | 기아 | 카니발 | `VAN` |
| 39 | 현대 | 포터2 | `TRUCK` |
| 45 | 기아 | 봉고3 | `TRUCK` |

**학습 데이터셋에서 제외된 차종**이라(AI Hub 가이드라인 p.5 *"버스, 화물차 등 제외"*) **유사 사례가 0건이 된다.** 등록·촬영·업로드를 다 하고 나서야 결과가 빈 것을 보게 된다.

- **목록에서 빼지 않는다.** 포터2·봉고3 은 국내 판매량 최상위권이고, 직접 입력이 불가능하므로(0-3) 빼면 사용자가 아예 막힌다
- **등록은 허용하되 안내를 띄운다.** 문안 예: *"이 차종은 분석 정확도가 낮을 수 있습니다"*
- 하드코딩보다 **`vehicleType` 으로 판별**할 것 — 마스터에 VAN·TRUCK 이 추가돼도 자동으로 걸린다
- ⚠️ **안내를 어디에 띄울지는 미확정**이다 → 6장

## 4. 화면 설계에 영향을 주는 동작 16가지

| # | 동작 | 화면에 미치는 영향 |
|---|---|---|
| 1 | **서버 정렬 순서에 의미가 없다** (제조사·모델명 둘 다) | **FE 가 둘 다 다시 정렬**한다 → 3-4 |
| 2 | **제조사 필터 파라미터가 없다.** 51종 전체가 한 번에 온다 | 제조사를 바꿔도 **재요청 없이 클라이언트에서 거른다.** 요청 수가 줄어 오히려 낫다 |
| 3 | **페이지네이션이 없다** (모델 목록·내 차량 둘 다) | **무한 스크롤을 만들지 말 것** |
| 4 | **같은 모델·연식을 여러 번 등록할 수 있다.** 중복 검사 없음 | *"이미 등록된 차량입니다"* 를 서버가 막아 주지 않는다. 필요하면 FE 가 안내 |
| 5 | **연식만 수정된다.** `modelId` 를 보내면 조용히 무시가 아니라 **400** | 수정 화면에서 **모델 드롭다운은 비활성**. PATCH 본문에 `modelYear` 만 담을 것 |
| 6 | **차량을 바꾸려면 삭제 후 재등록** | 5번의 귀결. 화면 흐름을 그렇게 짠다 |
| 7 | **삭제는 소프트 삭제.** 사고 이력이 있어도 **204**, 409 없음 | 삭제 확인 모달에 *"사고 이력은 남습니다"* 안내 |
| 8 | **삭제는 멱등.** 이미 삭제된 차량을 다시 지워도 204 | 중복 클릭 방어 로직이 없어도 안전 |
| 9 | **남의 차량·없는 차량 모두 404** (403 아님) | 404 를 *"권한 없음"* 으로 나눠 표시하지 말 것 |
| 10 | **목록이 비면 빈 배열.** 404 아님 | 빈 상태 화면을 404 처리에 넣지 말 것 |
| 11 | 목록은 **`created_at DESC`** — 최근 등록이 위 | 정렬 UI 를 따로 만들지 말 것 |
| 12 | 응답이 `{ "vehicles": [...] }` · `{ "vehicleModels": [...] }` 로 **감싸여 있다** | 배열이 바로 오지 않는다 → 2-1 |
| 13 | 등록·수정·목록이 **모두 같은 응답 모양** | **FE 가 타입 하나를 재사용**할 수 있다 |
| 14 | 연식 범위 **1980 ~ 2100** (경계 포함) | 입력 위젯 min/max |
| 15 | **VAN·TRUCK 4종은 분석이 되지 않는다** | 등록은 허용하되 **안내를 띄운다** → 3-5 |
| 16 | **지금은 로그인이 없어 전부 401** | 화면은 만들되 **실호출 확인은 인증 스토리 이후로** |

## 5. 구현되지 않은 것 · 아직 안 되는 것

### 5-1. Story 본문에 있지만 **만들면 안 되는 UI**

| Story 본문 | 실제 | FE 가 할 일 |
|---|---|---|
| *"목록에 없는 차량은 직접 입력 · 기타로 분류"* | **불가능.** `model_id` 가 `NOT NULL` + FK | **직접 입력 UI 를 만들지 말 것** |
| *"차급을 드롭다운으로 선택"* | **선택 불가.** 모델을 고르면 차급이 결정된다 | 차급은 **표시 전용** |
| *"차량 유형(승용·SUV·승합·화물) 선택"* | 마스터에 유형은 있으나 **등록 요청에는 없다** | 유형도 **표시 전용** |
| *"차급 5단계(경·소·준중·중·대형)"* | **4단계뿐.** 준중형 없음 | 3-2 의 4단계만 쓸 것 |

### 5-2. 로그인이 없어 지금은 전부 401

**차량 API 의 결함이 아니다.** 회원가입·소셜 로그인이 아직 구현되지 않았다.

| 막힌 곳 | 상태 |
|---|---|
| `SecurityConfig` 의 OAuth2 로그인 필터 | **없다.** 의존성·카카오/구글 설정·`permitAll` 은 다 있는데 필터 체인에만 빠져 있다 |
| 로그인 회원을 꺼내는 내부 컴포넌트 | **아직 예외를 던지는 임시 구현**이다 |

실측 (실 서버 · 시큐리티 필터 켬):

```
GET /actuator/health             200
GET /api/guides/checklist        200
GET /api/vehicle-models          401
GET /api/vehicles/me             401
GET /oauth2/authorization/kakao  500   ← 로그인 시작 경로인데 리다이렉트가 아니다
```

> **위 두 가지가 다 풀려야 차량 API 를 한 번이라도 호출해 볼 수 있다.** 로그인 필터만 붙이면 401 이 500 으로 바뀔 뿐이다.
> **FE 가 401 만 보고 "서버가 고장났다"고 판단하지 말 것.** 의도대로 동작하는 중이다.

**언제 풀리는가** — 인증(회원가입·소셜 로그인) 스토리 완료 시점. 별도 티켓이며 차량 스토리와 담당이 다르다. 일정은 재원님께 확인.

### 5-3. 서버가 고칠 예정 (FE 대응 불필요, 고쳐지면 이 문서를 갱신한다)

| 항목 | 지금 | 고친 뒤 |
|---|---|---|
| 모델명 정렬 (3-4) | 글자 수 순 | 가나다순 → **FE 의 모델명 정렬 코드 제거 가능** |
| 없는 경로가 500 (2-4) | 500 `INTERNAL_ERROR` | 404 `NOT_FOUND` |
