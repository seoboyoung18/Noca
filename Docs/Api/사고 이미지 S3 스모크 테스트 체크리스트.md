# 사고 이미지 S3 스모크 테스트 체크리스트

> **상태: 미검증** — 이 문서의 항목은 **아직 아무도 실행하지 않았습니다.**
> `S15P21A307-137` 구현은 단위·통합 테스트 777개로 검증했지만, 그 테스트는 전부
> **포트 더블 또는 네트워크를 타지 않는 로컬 서명 계산**입니다. 실제 S3 에 PUT/GET 을 한 적이 없습니다.
>
> 실행하지 않은 이유: 개발 머신에 AWS 자격증명은 있으나 **테스트 버킷 이름이 지정되어 있지 않고**,
> 팀 AWS 계정에 임의로 버킷을 만들거나 기존 버킷을 건드리지 않기로 했습니다.
>
> 작성 2026-09-10 · 기준 커밋 `feature/S15P21A307-137-be-accident-image-query`

---

## 왜 이 체크리스트가 필요한가

자동화 테스트가 **구조적으로 잡을 수 없는 것**이 세 가지 있습니다.

| 확인 못 하는 것 | 왜 |
|---|---|
| presigned 서명이 실제 S3 에서 통과하는지 | 서명은 로컬 계산이라 테스트는 "형태가 맞는지" 만 본다. 맞는지는 S3 만 안다 |
| `Content-Length` 정확값 강제가 실제로 동작하는지 | 신고 크기와 1바이트라도 다르면 403 이어야 하는데, 그 판정은 S3 쪽이다 |
| 버킷 CORS 가 브라우저 PUT 을 허용하는지 | 서버 코드와 무관하다. 버킷 설정 문제다 |

**이 셋 중 하나라도 어긋나면 FE 는 원인을 알기 어려운 403 을 받습니다.** 시연 전에 한 번은 돌려야 합니다.

## 0. 준비

```bash
# 자격증명 — 기본 체인을 쓴다. 액세스 키를 애플리케이션 설정에 넣지 않는다.
aws sts get-caller-identity

# 버킷 두 개. 서로 다른 버킷이어야 한다.
export STORAGE_STAGING_BUCKET=<staging 버킷명>
export STORAGE_SERVICE_BUCKET=<service 버킷명>
export AWS_REGION=ap-northeast-2

# 필요한 IAM 권한 (두 버킷 모두)
#   s3:PutObject · s3:GetObject · s3:HeadObject · s3:DeleteObject
#   GetBucketLocation 은 필요 없다 — 리전을 코드에서 명시한다
```

```bash
cd backend
./gradlew bootRun
```

기동 로그에 아래가 보여야 합니다. 안 보이면 버킷 변수가 안 들어간 것이고, 모든 이미지 API 가 503 입니다.

```
사고 이미지 저장소: S3 (region=ap-northeast-2)
```

로그인 세션 쿠키를 하나 확보하고(브라우저로 카카오 로그인 후 `SESSION` 쿠키 복사),
사고를 한 건 만들어 `{accidentId}` 를 확보합니다.

```bash
export COOKIE='SESSION=<복사한 값>'
export ACCIDENT_ID=<사고 ID>
export API=http://localhost:8080
```

## 1. 체크리스트

### ☐ 1. JPEG 업로드 URL 발급

```bash
ls -l front.jpg          # ← 실제 갤럭시 촬영본. 바이트 수를 정확히 확인한다
SIZE=$(stat -c %s front.jpg)

curl -sS -X POST "$API/api/accidents/$ACCIDENT_ID/images/upload-urls" \
  -H "Cookie: $COOKIE" -H 'Content-Type: application/json' \
  -d "{\"files\":[{\"originalFilename\":\"front.jpg\",\"contentType\":\"image/jpeg\",\"size\":$SIZE,\"angleCode\":\"FRONT\"}]}" \
  | tee issue.json
```

**통과 기준**
- HTTP 201
- `data.files[0].imageId` · `uploadUrl` · `requiredHeaders` · `expiresAt` 이 있다
- `requiredHeaders` 키가 **소문자** (`content-type` · `content-length`)
- `data.files[0].angleCode == "FRONT"`
- `uploadUrl` 호스트가 **staging 버킷**이다

### ☐ 2. 실제 S3 PUT

```bash
UPLOAD_URL=$(jq -r '.data.files[0].uploadUrl' issue.json)
IMAGE_ID=$(jq -r '.data.files[0].imageId' issue.json)

curl -sS -X PUT "$UPLOAD_URL" \
  -H "content-type: image/jpeg" -H "content-length: $SIZE" \
  --data-binary @front.jpg -w '%{http_code}\n'
```

**통과 기준** — `200`
**실패하면** `403 SignatureDoesNotMatch` — 헤더 이름·값이 `requiredHeaders` 와 정확히 같은지 먼저 보세요.

### ☐ 3. `Content-Length` 강제 확인 (음성 테스트)

```bash
# 1바이트 더 큰 파일을 같은 URL 로 올려 본다
cp front.jpg tampered.jpg && printf 'x' >> tampered.jpg
curl -sS -X PUT "$UPLOAD_URL" \
  -H "content-type: image/jpeg" -H "content-length: $((SIZE+1))" \
  --data-binary @tampered.jpg -w '%{http_code}\n'
```

**통과 기준** — **403** 이어야 합니다. 200 이 나오면 2단 방어가 동작하지 않는 것이고, 신고 크기를 믿을 수 없게 됩니다. → **이 경우 반드시 백엔드에 보고**

### ☐ 4. 완료 통보

```bash
curl -sS -X POST "$API/api/accidents/$ACCIDENT_ID/images" \
  -H "Cookie: $COOKIE" -H 'Content-Type: application/json' \
  -d "{\"images\":[{\"imageId\":$IMAGE_ID,\"size\":$SIZE}]}" | tee complete.json
```

**통과 기준**
- HTTP 200, `data.results[0].status == "COMPLETED"`
- `data.results[0].angleCode == "FRONT"`
- `data.results[0].assets` 가 **2개** (`RESIZED`·`THUMBNAIL`) — `ORIGINAL` 이 없어야 합니다

### ☐ 5. 파생 이미지 생성 확인

```bash
aws s3 ls "s3://$STORAGE_SERVICE_BUCKET/accidents/$ACCIDENT_ID/images/$IMAGE_ID/"
aws s3 ls "s3://$STORAGE_STAGING_BUCKET/accidents/$ACCIDENT_ID/images/$IMAGE_ID/"
```

**통과 기준**
- service 버킷: `resized.jpg` · `thumbnail.jpg`
- staging 버킷: `original.jpg`
- **버킷이 뒤바뀌어 있지 않을 것** — 원본이 service 에 있으면 7일 자동 삭제가 안 걸리고 EXIF 가 영구 보관됩니다

### ☐ 6. 목록 조회

```bash
curl -sS "$API/api/accidents/$ACCIDENT_ID/images" -H "Cookie: $COOKIE" | tee list.json
```

**통과 기준**
- `data.images[0].angleCode == "FRONT"`
- `assets` 가 `RESIZED`·`THUMBNAIL` 2개
- 각 asset 에 `url` 과 `expiresAt` 이 있다
- **`ORIGINAL` 이 없고, 어떤 `url` 에도 `/original.` 이 들어가지 않는다**
- **`s3Key` 필드가 응답에 없다**

### ☐ 7. 발급된 GET URL 로 썸네일 조회 + Content-Type

```bash
THUMB=$(jq -r '.data.images[0].assets[] | select(.variant=="THUMBNAIL") | .url' list.json)
curl -sS -o thumb.jpg -D - "$THUMB" | head -20
file thumb.jpg
```

**통과 기준**
- HTTP 200
- 응답 헤더 `Content-Type: image/jpeg`
- 내려받은 파일이 실제 JPEG 이고 긴 변이 320px 이하

### ☐ 8. URL 만료 동작

```bash
# app.accident-image.download-url-minutes=1 로 낮춰 재기동한 뒤 목록을 다시 받고
# 70초 기다렸다가 같은 URL 을 연다
sleep 70
curl -sS -o /dev/null -w '%{http_code}\n' "$THUMB"
```

**통과 기준** — **403** (`Request has expired`). 200 이면 만료가 걸리지 않은 것입니다.

### ☐ 9. ORIGINAL 이 외부에 노출되지 않는지

```bash
# (a) 응답 어디에도 원본 키가 없다
grep -c 'original' list.json complete.json      # → 0 이어야 한다

# (b) staging 버킷 오브젝트에 익명 접근이 안 된다
curl -sS -o /dev/null -w '%{http_code}\n' \
  "https://$STORAGE_STAGING_BUCKET.s3.$AWS_REGION.amazonaws.com/accidents/$ACCIDENT_ID/images/$IMAGE_ID/original.jpg"
```

**통과 기준** — (a) `0`, (b) **403**

### ☐ 10. HEIC 거절이 S3 를 건드리기 전에 일어나는지

```bash
curl -sS -X POST "$API/api/accidents/$ACCIDENT_ID/images/upload-urls" \
  -H "Cookie: $COOKIE" -H 'Content-Type: application/json' \
  -d '{"files":[{"originalFilename":"iphone.heic","contentType":"image/heic","size":1048576}]}' -w '\n%{http_code}\n'
```

**통과 기준**
- HTTP 400, `error.code == "SERVER_CONVERSION_UNSUPPORTED"`
- **S3 에 새 오브젝트가 생기지 않았고** `accident_image` 행도 늘지 않았다

### ☐ 11. 버킷 CORS (브라우저 PUT)

> curl 로는 확인되지 않습니다. **브라우저에서 해야 합니다.**

FE 개발 서버(`http://localhost:5173`)의 콘솔에서 1단계로 받은 `uploadUrl` 에 `fetch(url, {method:'PUT', headers, body:file})` 를 실행합니다.

**통과 기준** — CORS 오류 없이 200
**실패하면** 버킷 CORS 규칙에 아래가 필요합니다.

```json
[{ "AllowedOrigins": ["http://localhost:5173"],
   "AllowedMethods": ["PUT", "GET"],
   "AllowedHeaders": ["*"],
   "ExposeHeaders": ["ETag"],
   "MaxAgeSeconds": 3000 }]
```

### ☐ 12. 삭제와 정리

```bash
curl -sS -X DELETE "$API/api/accidents/$ACCIDENT_ID/images/$IMAGE_ID" \
  -H "Cookie: $COOKIE" -w '%{http_code}\n'
aws s3 ls "s3://$STORAGE_SERVICE_BUCKET/accidents/$ACCIDENT_ID/images/$IMAGE_ID/"
aws s3 ls "s3://$STORAGE_STAGING_BUCKET/accidents/$ACCIDENT_ID/images/$IMAGE_ID/"
```

**통과 기준** — 204, 두 버킷 모두 해당 접두사 아래가 비어 있음
