# 기술적 의사결정

## 목적

코드와 설정 파일 주석에 **이유가 적혀 있는** 결정만 모은다. 이 저장소는 주석에 판단 근거를
남기는 관행이 있어, 추측 없이 결정과 이유를 그대로 옮길 수 있다.

## 현재 구현

### 1. 작업 큐를 PostgreSQL로 한다 (메시지 브로커 없음)

| 항목 | 내용 |
| --- | --- |
| 결정 | 비동기 작업 큐를 별도 미들웨어 없이 DB 테이블 + `@Scheduled` 폴링으로 구현 |
| 구현 | 조건부 `UPDATE` 로 `QUEUED → PROCESSING` 전이. 부분 UNIQUE 인덱스로 중복 방지 |
| 근거 | `application.properties` 의 워커 설정 6종, `analysis_job` 등 상태 컬럼 |

부분 UNIQUE 인덱스가 `WHERE status IN ('QUEUED','PROCESSING')` 조건으로 걸려 있어, 같은 대상에
대해 진행 중인 작업이 둘 생기지 않는다. `processing-timeout` 이 지난 행은 고아로 보고 종결한다.

Redis가 이미 있는데 큐로 쓰지 않았다. Redis는 세션 전용이다.

### 2. `ddl-auto=validate` + 사람이 적용하는 마이그레이션

| 항목 | 내용 |
| --- | --- |
| 결정 | 스키마 변경을 자동 적용하지 않고 사람이 운영 DB에 적용 |
| 안전장치 | CI `migration-guard` 잡이 미적용 SQL이 있으면 배포를 멈춤 |
| 근거 | `.gitlab-ci.yml:60~` 주석 |

이유가 CI 주석에 있다 — "자동으로 돌리면 실패했을 때 조용히 지나가고, `ddl-auto=validate` 라서
어긋나면 그 API 만이 아니라 앱 전체가 안 뜬다."

가드는 DB를 보지 않고 **파일 원장**을 본다. `/home/ubuntu/.a307-applied-migrations` 에
`<내용 해시> <경로>` 를 한 줄씩 적는다. 경로만이 아니라 내용 해시까지 적는 이유도 주석에 있다 —
"적용한 뒤 누가 SQL 을 고치면 다시 멈춰야 한다."

### 3. 이미지 바이트를 백엔드가 중계하지 않는다

| 항목 | 내용 |
| --- | --- |
| 결정 | 브라우저 → S3 직접 업로드(presigned PUT), AI 서버 → S3 직접 다운로드(presigned GET) |
| 효과 | 백엔드 메모리·대역폭 절약, AI 서버에 S3 자격증명 불필요 |
| 근거 | `AccidentImageController.issueUploadUrls`, `AI/server/app/infrastructure/image_fetcher.py` |

### 4. 의존성을 최소로 유지하고, PDF만 예외로 둔다

`backend/build.gradle` 주석 그대로다.

> 이 저장소는 새 의존성을 넣지 않는 것을 관례로 지켜 왔다(GMS 호출도 RestClient 로 버텼다).
> PDF 는 그 관례의 예외다 — JDK 만으로는 PDF 를 만들 수 없다.

라이선스 판단까지 기록돼 있다 — iText 7은 AGPL이라 제외, Open HTML to PDF는 LGPL이라 채택.
OpenPDF는 저수준 생성용, PDFBox 단독은 기존 PDF 조작용이라 맞지 않았다.

### 5. PDF HTML을 LLM에게 맡기지 않는다

`build.gradle` 주석:

> 서버가 HTML 을 만든다. LLM 에게 마크업을 맡기지 않는다(구조화 출력의 mime_type 이
> application/json 만이라 HTML 은 스키마를 강제할 수 없고, PDF 는 사용자가 정비소에 들고 갈
> 문서라 레이아웃을 서버가 통제해야 한다).

### 6. 배포 이미지에서 torch를 CPU 휠로 바꾼다

`AI/server/Dockerfile` 주석:

> `AI/requirements.txt` 는 torch==2.6.0+cu124 다. 배포 대상 Lightsail 인스턴스에는 GPU 가 없다.
> CUDA 휠을 넣으면 이미지가 6GB 를 넘는데 실제로는 CPU 로 돈다.

`shared/vision/dinov2.py` 가 `"cuda" if torch.cuda.is_available() else "cpu"` 로 내려가므로
결과는 같고 느릴 뿐이다. GPU 인스턴스로 옮기면 이 블록을 되돌린다고 적혀 있다.

### 7. DINOv2 가중치를 이미지에 굽는다

`AI/server/Dockerfile` 2단계가 빌드 중에 `AutoModel.from_pretrained` 를 호출해 가중치를 넣고,
런타임에 `HF_HUB_OFFLINE=1` 로 둔다. 이유는 "런타임에 Hugging Face 에서 받게 두면 첫 요청이
느리고, 네트워크가 막히면 아예 죽는다."

### 8. Docker 이미지 안에서 Gradle을 돌리지 않는다

`backend/Dockerfile` 주석:

> 처음엔 멀티스테이지로 컨테이너 안에서 빌드했는데, 이 개발 환경에서는 컨테이너 egress 가
> 막혀 있어 Gradle 배포본·의존성을 받지 못했다(호스트는 되고 이미지 pull 도 되는데
> 컨테이너에서만 안 나간다).

미리 만든 jar를 쓰니 이미지 빌드가 수 초로 끝났고, 레이어드 jar로 쪼개 실제 전송을
97MB → 8.9MB로 줄였다.

### 9. AI 컨테이너에 메모리 상한을 건다

`.gitlab-ci.yml` 의 `deploy-ai` 잡 주석:

> 🔴 메모리 상한은 선택이 아니다. 이 박스에는 PostgreSQL 이 같이 있고, 상한이 없으면 모델이
> 메모리를 먹다가 DB 를 끌고 내려간다. 그러면 BE 도 같이 죽는다 — ddl-auto=validate 라
> DB 가 없으면 재기동도 안 된다.

`--memory=6g --memory-swap=6g --cpus=3` 이 그 결과다.

### 10. 비밀값을 CI 변수에 두지 않는다

`.gitlab-ci.yml` 헤더 주석:

> 백엔드 비밀값(DB·OAuth·AWS 키)은 서버의 `/etc/a307/backend.env` 에만 있고 컨테이너에
> `--env-file` 로 들어간다. CI 변수로 옮기면 파이프라인 로그·아티팩트·포크 MR 로 새어 나갈
> 경로가 늘어난다.

CI 변수에 둔 것은 `VITE_API_BASE_URL` · `VITE_KAKAO_JS_KEY` 둘뿐이고, 그 둘은 어차피 번들에 박혀
브라우저로 나가므로 비밀이 아니라고 적었다.

### 11. 정비소 검색을 카카오 지도 SDK 직접 연동으로 한다

루트 `README.md` 기능 상태표:

> `ShopsView` 가 브라우저에서 카카오 지도 SDK 를 직접 부른다. 지도 렌더링과 검색 결과가 같은
> SDK 에서 나와 좌표가 어긋나지 않고, 서버를 한 번 거치지 않아 응답이 빠르다.

백엔드 `GET /api/repair-shops` 는 서버 경유가 필요해질 때를 위해 남겨 두었다.

### 12. 부품이 불확실하면 `null` 로 둔다

`Docs/AI/이미지 입력 및 검색 corpus 결정사항.md`:

> 검증되지 않은 행은 `partCode = null` 로 남기고 `VECTOR_ONLY` 로 처리한다.
> 부품을 틀리게 부여하는 것보다 null 이 견적 안전성 측면에서 낫다.

`VECTOR_ONLY` 는 견적 항목이 되지 못하고 손상유형만으로 유사 사례를 찾는다.

### 13. 컨테이너를 root로 돌리지 않는다

백엔드·AI 이미지 모두 `uid 1001` 전용 계정을 만들어 `USER` 를 바꾼다.

## 관련 소스코드

- `backend/build.gradle` — 의존성·라이선스 판단
- `backend/Dockerfile` · `AI/server/Dockerfile` — 빌드 전략
- `.gitlab-ci.yml` — 마이그레이션 가드, 비밀값 정책, 메모리 상한
- `Docs/AI/이미지 입력 및 검색 corpus 결정사항.md` — 부품 미확정 정책

## 근거 자료

위 결정은 모두 **소스·설정 파일 주석에 이유가 적혀 있는 것만** 옮겼다. 주석이 없는 결정은
이 문서에 넣지 않았다.

## 확인 필요 항목

- **Redis를 큐로 쓰지 않은 명시적 이유** — 코드 주석에서 확인하지 못함 (`추정`: DB 트랜잭션과 큐 상태를 한 곳에서 관리하려는 의도)
- **부분 UNIQUE 인덱스 4개의 정확한 대상 테이블** — DDL 전수 확인을 하지 못함
- **`ANALYSIS_PROFILE=mock` 도입 시점과 배경** — 코드에 존재는 확인되나 결정 기록은 확인하지 못함
