## 데이터 구조

- 초기 임베딩 대상 : 전체 사고 이미지 중 **632,694장**
- 견적서와 연결 가능한 이미지 : **약 12만 장**
- **사고 ID 1개에 여러 장의 이미지와 견적서 1개 연결**
- 견적서 : 부품비, 작업별 공임, 도장비, 기타 비용, 차감액, 부가세 등 포함
- 수리 내역을 정규화한 결과, 부위·작업 방식의 고유 조합 = **129종**

## 주요 확인 결과

- 한 사고를 여러 각도에서 촬영한 이미지가 존재 → 이미지 한 장보다 **사고 ID 단위로 묶어 관리**
- 이미지에는 파손 부위 정보가 있고 견적서에는 여러 수리 항목이 포함되어 있지만, **특정 이미지의 파손 부위와 견적서의 개별 항목이 직접 연결되어 있지는 않음**
- 따라서 현재 데이터만으로는 특정 부위의 정확한 수리비를 바로 정답으로 만들기 어려움
- 사고 ID를 기준으로 이미지와 전체 견적을 연결 가능 → **유사 사고 검색과 전체 예상 견적 범위 산출**에 활용
- 수리 방식은 도장, 판금, 수리, 교환 등으로 구분 → 유사 사례의 수리 방법을 비교하는 기준으로 활용

## 설계 반영

- 검색 단위는 개별 이미지가 아니라 **사고 사례(case_id)** 중심으로 구성
- 여러 장의 이미지에서 추출한 특징을 통합하여 유사 사고를 검색
- 검색 결과는 단일 금액이 아니라 **중앙값·최솟값·최댓값 등 견적 범위**로 제공
- Retrieval 성능은 시각적 유사성뿐 아니라 **차종·파손 부위·수리 방식의 유사성**도 함께 평가
- 부위별 견적 기능이 필요할 경우, 이미지의 파손 부위와 견적서 항목을 연결하는 **추가 매핑 규칙 또는 라벨링 과정**이 필요

**유사 사고 사례와 예상 비용 범위를 근거와 함께 제공하는 서비스**

